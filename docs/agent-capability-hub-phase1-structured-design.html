Structured Design / Phase 1

Agent Capability Hub

Agent Capability Hub 是部门级 Agent 外围能力登记、发现和统一调用平台。阶段一聚焦 HTTP MCP 服务的页面登记，以及只暴露 search 和 execute 两个工具的基础 MetaMCP 网关。

日期：2026-06-02 项目新名称：Agent Capability Hub 阶段一：MCP Registry + MetaMCP Gateway 连接方式：HTTP MCP 优先
结论 定位 范围 架构 模型 MetaMCP Web 登记 迁移关系 验收 后续

1. 设计结论

阶段一不追求完整治理平台，先跑通“登记 MCP 服务 -> 发现工具 -> 统一执行”的最小闭环。

Decision

一期核心

管理员通过 Web 页面登记 HTTP MCP 服务，平台同步服务下的工具清单和参数 schema，并通过统一 MetaMCP 对外暴露能力发现与执行入口。

固定工具

对 Agent 暴露的 MetaMCP 工具固定为 search 和 execute。后台 MCP 工具数量变化不影响 Agent 侧配置。

执行边界

一期允许执行查询类工具，操作类工具可以登记和搜索，但执行时明确拒绝，为后续审批、确认、审计和权限治理留出口。

2. 产品定位

项目从知识库管理器升级为面向 Agent 的能力管理和调用入口。

Platform
一句话定义： Agent Capability Hub 是部门级 Agent 能力中心，用于登记、管理、发现和调用 HTTP MCP 服务中的工具，并把分散的 MCP 能力收敛为一个稳定 MetaMCP 网关。

为什么改名

  • wiki-manager 暗示项目只服务知识库，已经不能覆盖 MCP、工具、API、Skill 等能力来源。
  • Agent Capability Hub 更准确表达“Agent 可使用的外围能力中心”。
  • 保留知识库作为一种能力来源，而不是唯一核心。

面向用户

  • 管理员：登记 MCP 服务、维护工具元数据、控制启停状态。
  • Agent 使用者：通过 MetaMCP 搜索并执行可用能力。
  • 前端设计工程师：基于页面定义先输出完整平台设计稿。

平台价值

  • Agent 只接一个 MCP，而不是接很多 MCP。
  • 后台 MCP 服务可以动态新增、下线、改描述。
  • 后续权限、日志、Profile 和操作治理都在服务端统一收敛。

3. 阶段一范围

本期只做平台骨架和核心网关闭环，明确推迟审计、复杂试运行和操作类治理。

Phase 1
模块 本期要做 本期不做
MCP 服务登记 支持页面登记 HTTP MCP 服务，包括服务标识、URL、headers、描述、标签、启停状态。 不支持 stdio MCP；不做服务托管；不管理远端服务生命周期。
工具清单同步 连接已登记服务，读取 tools 清单，保存工具名称、描述、input schema、同步时间和状态。 不做复杂 schema 可视化编辑器；不做自动质量评测。
工具元数据 允许维护服务级和工具级展示信息，包括别名、标签、能力类型、调用示例。 不做多版本元数据审批；不做多人协同审核。
MetaMCP 网关 对外暴露 search 和 execute 两个工具。search 查询能力目录；execute 执行查询类工具。 不直接暴露所有后台工具；不执行操作类工具。
Web 页面 提供 MCP 服务列表、新增/编辑、服务详情、工具清单、基础 MetaMCP 说明页。 日志、Profile、审计、试运行工作台可先出设计稿，不进入一期实现验收。

4. 一期架构

系统由 Web 管理端、平台 API、MCP Registry、MetaMCP Gateway 和 HTTP MCP Client 组成。

Architecture
1. 页面登记 管理员在 Web 页面登记 HTTP MCP 服务，保存连接信息和元数据。
2. 同步 tools 平台通过 HTTP MCP Client 拉取远端 tools 清单并写入 Registry。
3. search 发现 Agent 调用 MetaMCP search，按关键词、标签、服务、类型检索工具。
4. execute 调用 Agent 提供 service、tool、arguments，平台校验后转发给对应 MCP 服务。
5. 结果返回 平台返回标准化结果，包含服务、工具、原始结果和错误信息。
一期的核心风险不是页面复杂度，而是 MCP 协议连接、工具 schema 同步和 execute 转发的可靠性。 因此页面以登记和可见性为主，日志和审计先保留数据结构方向，不作为第一批硬功能。

5. 核心数据模型

模型要支持未来扩展，但一期字段保持可落地。

Model
对象 关键字段 说明
mcp_service service_key, name, endpoint_url, headers, description, tags, status 代表一个可连接的 HTTP MCP 服务。service_key 是 execute 调用时使用的稳定标识。
mcp_tool service_key, tool_name, display_name, description, input_schema, tool_type, examples 代表某个 MCP 服务下的一个工具。工具真实名称来自远端 MCP，展示信息可在平台覆盖。
tool_type overview, search, detail, action 一期允许前三类执行；action 可登记、可搜索、不可执行。
sync_state last_synced_at, last_success_at, last_error, tool_count 用于页面展示 MCP 服务是否成功同步 tools。

6. MetaMCP 工具契约

MetaMCP 只暴露两个稳定工具，后台工具由参数选择。

MCP Contract

search

查询 MCP 服务和工具清单，返回匹配到的服务、工具说明、参数 schema 和调用示例。

{
  "query": "mysql 报表查询",
  "service": "mysql",
  "tool_type": "search",
  "limit": 10
}

execute

执行指定服务下的指定工具。参数名建议使用 arguments，避免和协议层 params 混淆。

{
  "service": "mysql",
  "tool": "query_sql",
  "arguments": {
    "db": "whjcbb",
    "sql": "select abc from aaa",
    "limit": 10
  }
}
工具 输入 输出 一期限制
search query, service, tags, tool_type, limit 匹配工具列表、描述、schema、示例、是否可执行。 先使用关键词、标签、描述匹配；语义检索可后续增强。
execute service, tool, arguments 标准化执行结果、原始 MCP 返回、错误信息。 只执行 overview/search/detail；拒绝 action。
命名建议： execute 的第三个参数建议叫 arguments，因为 MCP tool call 本身通常也有 arguments 概念。 params 容易和 HTTP 请求参数、MCP 协议参数、内部转发参数混在一起。

7. Web 登记流程

页面一期要服务“把 MCP 服务接入平台”这件事，而不是一次做完整后台。

Web
步骤 页面动作 后端动作 成功结果
新增服务 填写服务标识、名称、URL、headers、描述、标签。 保存服务配置，状态为 configured。 服务出现在列表中。
测试连接 点击测试连接。 尝试访问 MCP endpoint 并读取基础能力。 返回连接成功或错误原因。
同步工具 点击同步 tools。 调用远端 MCP list tools，写入工具清单。 展示工具数量、同步时间、失败信息。
维护元数据 编辑工具类型、标签、调用示例和展示描述。 保存平台侧覆盖信息，不改远端 MCP。 search 返回更适合 Agent 使用的说明。

8. 与现有代码的关系

现有 wiki-manager 能力不需要废弃，但要降级为平台中的一种能力来源。

Migration

保留

  • 现有 FastAPI 服务结构可以继续作为平台 API 基础。
  • 现有 MCP server 中的 search / ask 思路可迁移为知识库能力。
  • 现有存储、服务层和后端适配代码可作为知识库来源模块保留。

调整

  • 服务名称从 wiki-manager 逐步迁移到 agent-capability-hub。
  • 现有 MCP server 需要从“知识库工具”改为“MetaMCP 网关工具”。
  • 数据模型需要新增 MCP 服务和 MCP 工具注册表。

9. 阶段一验收标准

验收围绕最小闭环，不把未来治理能力纳入硬标准。

Acceptance
  1. 管理员可以在 Web 页面新增、编辑、启停一个 HTTP MCP 服务。
  2. 管理员可以测试 MCP 服务连接，并同步远端 tools 清单。
  3. 页面可以展示服务详情、工具列表、工具 schema、工具类型和调用示例。
  4. MetaMCP 对外只暴露 search 和 execute 两个工具。
  5. 调用 search 可以通过关键词找到相关 MCP 服务和工具，并返回描述、schema 和示例。
  6. 调用 execute 可以执行已登记的查询类 MCP 工具，并返回实际结果。
  7. 调用 execute 执行 action 类型工具时，返回明确拒绝原因。
  8. 当远端 MCP 连接失败、工具不存在、参数不合法时，返回可读的标准化错误。

10. 二期和预留方向

以下能力应在页面设计中预留，但不进入一期工程验收。

Future

审计与日志

记录 search、execute 的请求、命中、耗时、成功状态、错误和响应样例，用于排查和运营。

Profile 与权限

按项目、团队或场景控制哪些 MCP 服务和工具可见、可执行。

操作类工具治理

对 action 工具增加风险等级、二次确认、dry-run、审批和强审计。
