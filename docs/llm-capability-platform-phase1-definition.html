Product Definition / Phase 1

大模型外围能力管理平台

本项目从单一的知识库管理系统，调整为面向部门通用大模型应用的外围能力管理平台。 平台不维护模型本身，也不代理模型推理，而是统一维护知识库、MCP API 等可被大模型调用的能力，并通过 MetaMCP 对外提供发现、检索和试运行入口。

1. 新产品定位

新的项目重点不是管理模型，而是管理模型可以使用的外围能力。

Platform
一句话定义： 本项目是部门级大模型外围能力管理平台，用于注册、管理、检索、试运行和审计知识库能力与 MCP API 能力，并将这些能力通过统一的 MetaMCP 入口暴露给大模型应用。

不做什么

  • 不维护模型本身。
  • 不实现模型推理代理。
  • 阶段一不做有副作用操作类工具。
  • 阶段一不做完整企业级权限体系。

做什么

  • 管理知识库对接与检索能力。
  • 管理外部 MCP API 服务。
  • 提供 Web 管理、查看和试运行入口。
  • 记录所有调用日志和执行结果。

平台价值

  • 让大模型先发现能力，再调用能力。
  • 把分散工具统一成可治理资产。
  • 为后续操作类工具、权限、审批打基础。
  • 降低部门内 MCP 工具接入和复用成本。

2. 阶段一范围

阶段一先把平台底座跑通：知识库能力、MCP API 管理、Web 界面、MetaMCP 查询入口和调用日志。

Phase 1
模块 阶段一要做 阶段一不做
知识库能力 保留并继续支持现有知识库管理、文档入库、后端对接、检索和问答能力。 不把知识库做成唯一核心；它是平台中的一种能力来源。
MCP API 管理 服务端维护 MCP 服务配置，读取工具清单，管理工具元数据，支持原始 MCP 工具试运行。 不接入操作类 MCP 工具执行，不做复杂工作流编排。
MetaMCP 提供能力检索和查询类能力运行入口，让模型通过少量稳定工具发现和调用后台能力。 不直接把所有后台工具无差别暴露给模型。
Web 界面 提供管理员和访客两类视图。管理员可编辑 MCP 配置，访客只读查看能力目录和试运行结果。 不做完整登录、组织架构、细粒度权限和审批流。
调用日志 所有 MetaMCP 和原始 MCP 调用都记录匹配、参数校验、耗时、成功状态和响应样例。 不保存无限量完整响应；敏感字段脱敏策略先预留，后续增强。

3. 核心对象模型

阶段一需要从“知识库账本”扩展为“能力注册表 + 能力执行网关”。

Model

能力来源

能力来源表示平台连接到的后台系统。阶段一包括 knowledge_base 和 mcp_api。 后续可以扩展到 OpenAPI、CLI、数据库工具和内部业务系统。

能力条目

能力条目是一个可被发现或调用的最小单元，例如某个知识库的检索能力，或某个 MCP 服务里的一个 tool。 每个能力条目需要名称、描述、标签、参数 schema、返回样例和来源信息。

能力类型

所有能力按 overview、search、detail、action 分类。 阶段一只支持前三类查询能力；action 作为第二阶段能力。

类型 定义 是否有副作用 阶段一状态
overview 列出资源、目录、状态、可用范围。 否 支持
search 根据关键词、语义或条件寻找候选结果。 否 支持
detail 读取某个明确对象的详细信息。 否 支持
action 创建、修改、删除、触发执行、变更状态。 是 阶段一登记但不执行，第二阶段启用

4. Web 管理界面

部门通用配置放在服务端，日常管理不再依赖 CLI。CLI 可以保留为安装、启动、初始化和运维入口。

UI

管理员视图

  • 查看平台概览：能力来源数量、MCP 服务数量、工具数量、最近调用状态。
  • 管理 MCP API：新增、编辑、启停、刷新工具清单、查看连接状态。
  • 维护工具元数据：名称、描述、标签、类型、参数 schema、响应样例。
  • 管理知识库能力：查看 KB、同步状态、检索/问答能力是否可用。
  • 试运行 MetaMCP 和原始 MCP 工具。
  • 查看调用日志和失败详情。

访客视图

  • 只读查看能力目录。
  • 查看 MCP 服务和工具的基础说明。
  • 按关键词检索可用能力。
  • 试运行查询类工具。
  • 查看自己的或公开的试运行结果。
  • 不能新增、编辑、删除或启停 MCP 配置。
阶段一的“管理员/访客”主要是界面角色和操作边界，不等同于完整安全权限体系。 可以先用简单配置、固定入口或开发期身份标识区分角色；后续再接入正式登录、组织权限和审计策略。

5. MetaMCP 与试运行

MetaMCP 是平台对大模型暴露的稳定入口；原始 MCP 仍可在 Web 后台被查看和试运行。

MCP
1. 注册来源 管理员在 Web 端登记知识库或 MCP API 服务，服务端保存连接配置。
2. 同步工具 平台读取 MCP tools 或知识库能力，生成统一能力条目。
3. 检索能力 MetaMCP 根据用户问题检索候选能力，返回说明、类型和参数要求。
4. 执行查询 MetaMCP 或 Web 试运行调用查询类工具，记录完整调用日志。
试运行对象 用途 输入 输出
MetaMCP 检索 验证模型是否能通过平台找到正确能力。 自然语言问题、类型过滤、来源过滤。 候选能力列表、匹配原因、参数摘要。
MetaMCP 运行 验证平台能否用统一入口执行查询类能力。 能力 ID、参数 JSON。 标准化结果、原始结果样例、耗时和日志 ID。
原始 MCP 工具 验证某个后台 MCP tool 本身是否可用。 MCP 服务、tool 名称、参数 JSON。 原始 MCP 响应、错误信息、耗时和日志 ID。
知识库能力 验证知识库检索和问答能力是否可用。 知识库、问题、top_k、后端选择。 检索片段、回答、来源和耗时。

6. 调用日志

日志是阶段一的基础能力之一，用于排查工具匹配、参数格式、后端调用和响应质量。

Audit
字段 说明
call_id 单次调用唯一 ID，用于 Web 展示和问题排查。
entrypoint 调用入口，例如 metamcp_search、metamcp_run、raw_mcp_run、kb_search。
source_id / tool_id 实际命中的能力来源和能力条目；未命中时为空并记录失败原因。
tool_type 能力类型：overview、search、detail、action。
matched 是否匹配到正确 MCP 或能力条目。
params_valid 请求参数是否符合工具参数 schema。
request_params 请求参数快照。阶段一可先完整记录，结构上预留脱敏策略。
started_at / finished_at / duration_ms 调用开始时间、返回时间和耗时。
success / error_message 是否调用成功，以及标准化错误信息。
response_sample 响应样例。建议限制长度，避免保存大响应或敏感内容。

8. Claude Code 接入 CLI

平台需要提供 CLI，帮助用户把 MetaMCP 接入 Claude Code，并通过 Project Profile 控制不同项目可见的 MCP 服务。

CLI
目标： 用户可以通过 CLI 将平台的 MetaMCP 配置写入 Claude Code 配置文件，并绑定一个服务端维护的 Project Profile。 例如平台已连接 mysql 和 hive 两个查询 MCP，某项目绑定 safe-readonly profile，profile 中将 hive 加入黑名单后，该项目访问 MetaMCP 时会携带 profile 请求头，服务端不会返回 hive 下的任何工具，也不允许通过运行接口调用这些工具。

配置范围

  • 项目级配置：写入当前项目的 Claude Code 配置，并绑定某个 Project Profile，适合项目团队共享同一套能力限制。
  • 用户级配置：写入用户全局 Claude Code 配置，适合个人默认接入平台 MetaMCP。
  • 项目级和用户级同时存在时，建议服务端按最终请求头执行过滤；CLI 负责生成清晰、可检查的配置。

Project Profile

  • Profile 是服务端维护的能力访问策略，例如 frontend-project、data-project、safe-readonly。
  • Profile 内部可以包含黑名单或白名单，名单以 MCP 服务级别为主。
  • 黑名单表示不可见、不可调用；白名单表示唯一允许访问。
  • 黑名单和白名单不建议同时配置；如果同时出现，服务端应采用更保守策略，以白名单限定范围后再应用黑名单。
能力 说明 示例
添加项目级 MetaMCP 把平台 MCP 服务写入当前项目配置，并绑定指定 profile。 wiki metamcp add --scope project --url http://wiki.local/mcp --profile safe-readonly
添加用户级 MetaMCP 把平台 MCP 服务写入用户全局配置，作为个人默认 MCP 入口。 wiki metamcp add --scope user --url http://wiki.local/mcp --profile data-project
创建 Profile 在服务端创建或更新能力访问策略。 wiki metamcp profile create safe-readonly --deny hive
更新 Profile 调整 profile 内的黑名单或白名单。 wiki metamcp profile update frontend-project --allow mysql --allow wiki
查看有效配置 展示当前项目或用户级 MetaMCP 配置、请求头和绑定 profile。 wiki metamcp config --scope project

请求头约定

Claude Code 调用 MetaMCP 时优先携带 X-Wiki-MetaMCP-Profile，服务端根据 profile 解析能力访问范围。 如需调试或兼容，也可以保留 X-Wiki-MetaMCP-Allow 和 X-Wiki-MetaMCP-Deny 作为显式名单请求头。

服务端强制执行

Profile 策略不能只停留在客户端。MetaMCP 检索接口必须过滤候选能力；MetaMCP 运行接口也必须再次校验工具所属来源。 这样即使模型知道某个被屏蔽 tool_id，也无法绕过检索直接调用。

9. 初始 Roadmap

Roadmap 暂按产品能力成熟度拆分，后续可以再映射到实际开发里程碑。

Roadmap
阶段 目标 主要能力
阶段一：查询类能力平台 完成知识库 + MCP API 的注册、管理、检索、试运行和日志闭环。 Web 管理端、访客视图、MCP 服务配置、工具同步、MetaMCP 查询入口、原始 MCP 试运行、调用日志、Claude Code 接入 CLI、Project Profile、服务级白名单和黑名单。
阶段二：操作类能力治理 允许有副作用的 action 类工具进入平台，但必须可控。 操作类工具注册、风险等级、二次确认、审批预留、dry-run、幂等性声明、操作审计。
阶段三：多来源能力扩展 从 MCP 和知识库扩展到更多外围工具来源，并建立查询类能力质量评测。 OpenAPI 导入、CLI 工具封装、数据库查询工具、内部系统能力接入、能力检索增强、知识库检索和 MCP 查询工具测试问题集、命中率、失败率、平均耗时和答案样例统计。
阶段四：企业级治理 把平台从部门工具升级为可长期运营的企业基础设施。 正式权限、组织空间、密钥管理、脱敏策略、调用配额、质量评测、可观测性报表。

10. 未来可选能力

以下能力不进入当前阶段一重点，仅作为平台长期演进方向保留。

Optional

Skill Registry

  • 将 skill 作为一种复合能力资产登记，记录名称、适用场景、触发说明、版本、标签和资源清单。
  • 通过检索式 MetaMCP 按需发现 skill，减少启动时全量加载所有 skill 的上下文成本。
  • 用 MCP prompt 暴露 skill 的工作流说明和提示模板。
  • 用 MCP resource 暴露模板文件、参考文档、示例和 schema。

Skill Materialization

  • 按需获取 skill bundle manifest、资源文件和任务上下文。
  • 脚本文件可以作为资源被查看，但不应让模型自由下载后直接执行。
  • 未来如需执行 shell、Python 或 Node 脚本，应通过受控 runner，纳入权限、审计、沙箱和依赖检查。
  • 该能力适合放在操作类能力治理成熟之后再推进。

代码图谱 / CodeGraph

未来可选能力。暂定使用 codegraph 方向补充代码仓库结构分析、依赖关系、代码语义检索和研发辅助能力。 具体范围后续补充。

12. 待继续确认的问题

以下问题会影响阶段一的具体实现方案，但不阻塞当前产品定义成型。

Next
  • 阶段一 Web 角色区分采用什么方式：固定配置、URL 模式、简单口令，还是先仅做 UI 角色切换。
