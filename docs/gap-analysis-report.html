🏛️ 团队知识与工具治理支撑评估

核心治理闭环 注册 → 分类 → 策略 → 执行 → 审计 已完整拉通。 以下逐一评估实际治理场景的支撑情况:

✅ 工具注册与发现 管理员可注册外部 MCP 服务、同步工具、分类标记。AI Agent 通过 MetaMCP search 浏览可用能力。满足"有什么工具"的治理需求。
✅ 权限与访问控制 Profile 机制支持按团队/项目隔离: 服务级 allow/deny + 资源级 KB/Repo 允许列表。CLI 一键绑定配置。满足"谁能用什么"的治理需求。
✅ 知识库管理与共享 KB 独立管理、多后端同步、RBAC 成员管理、Profile 控制可见范围。Wiki 内建 MCP 让 Agent 可直接检索。满足"知识在哪里、谁能看"的治理需求。
✅ 调用审计与故障追踪 每次调用全量记录 (谁调了什么、成功/失败/拦截、耗时、请求响应)。故障归因到具体阶段和责任方。满足"出了什么问题、谁的锅"的治理需求。
⚠️ 检索策略运营 多后端检索策略的后端链路已通，但管理员无法通过 UI 配置 KB 默认检索后端和 Profile 级覆盖。需补充前端 UI 才能实际运营。
⚠️ 运营趋势与报警 调用统计无时间趋势、无分位数延迟、无错误 Top-N 排行、无主动报警。可事后查日志，但不支持"趋势变差了及时感知"。
⚠️ Action 工具安全管控 写操作工具只能注册、不能执行。无风险分级、无审批流、无试运行。团队如果有写入类 MCP 工具，当前无法安全地开放。
⚠️ 工作流编排 多步骤知识处理工作流 (如: 文档入库 → 自动抽取 → 质量检查 → 发布) 无任何支撑。导航入口已有，但仅占位页。

按治理影响排序，优先修复断链点

    断链修复前端优先级 P0
  2. 统计页增强: 时间区间 + 穿透链接 StatsView 增加 24h/7d/30d 快捷按钮 + bucket 参数传递 + 时间序列展示。表格行增加点击跳转到已过滤的 LogsView (通过 URL hash 传参)。后端已支持，仅前端工作。
    体验增强前端优先级 P1
  3. 仪表盘扩展: 覆盖知识 + 观测 DashboardView 增加: KB 同步失败计数、代码仓库状态、最近 24h 调用量、近期错误 Top 5。让仪表盘成为真正的"运维入口"。
    体验增强全栈优先级 P1
  4. 定义工作流 MVP 范围 当前 WorkflowView 是空壳。建议先明确最小场景 (如: 文档入库自动同步 + 质量检查通知)，再设计数据模型和 API。不建议盲目开发。
    规划产品定义优先级 P2
  5. Action 工具治理设计 当团队有写入类 MCP 工具需求时启动。建议从"风险分级 + 确认执行"两级开始，审批流和试运行后续迭代。
    延期项全栈优先级 P2
  6. 日志运维: 导出 + 保留策略 长期运行后 tool_call_logs 表会膨胀。增加定时清理 (如保留 90 天) + CSV 导出按钮。大负载截断 (request_json > 100KB) 也应考虑。
    运维后端优先级 P2
