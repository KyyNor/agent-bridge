工作流任务 Excel 导入设计

状态：待实施计划  ·  日期：2026-07-15  ·  范围：工作流任务进度页
在现有“任务进度”页增加 Excel 导入能力。用户上传 .xlsx 文件后先获得服务端预览，确认无错误后再由服务端原子写入任务队列；自动获取任务和手动导入任务继续复用同一套任务语义。

1. 已确认的产品决策

入口
任务进度页内弹窗导入，不新增独立页面
文件范围
首期只支持 .xlsx，最多 5,000 条数据行
工作表
只读取第一个工作表
提交方式
后端预览 → 用户确认 → 后端提交

Excel 列规则

列要求落库位置
task_key必填，去除首尾空白后不能为空任务固定字段
task_version可选，空值按空字符串处理任务固定字段
type可选，空值按空字符串处理任务固定字段
其他列列名作为 payload key；空单元格不写入 payloadpayload JSON 对象

同一文件内以 task_key + task_version 判断重复；空行忽略。第一行必须是表头，表头重复、缺少 task_key、单行 task_key 为空等问题在预览阶段逐行提示。

2. 用户流程

  1. 任务进度页工具栏新增“下载 Excel 模板”和“导入 Excel”。
  2. 用户选择文件后，弹窗显示解析状态；服务端完成解析、校验和冲突预估。
  3. 预览显示总行数、可导入数、新增数、更新数、跳过数和错误数，并列出行号、task_key、type、预期动作与错误信息。
  4. 存在错误时“确认导入”禁用；用户可重新上传或关闭弹窗。
  5. 确认成功后关闭弹窗、刷新当前工作流任务列表、保留导入统计提示，并清理本次导入快照。

3. 技术架构

采用“后端预览 + 后端确认”的两阶段方案。预览时服务端保存标准化任务快照和预览报告，确认时只接受服务端生成的 import_id，不信任前端回传的任务内容。

前端
WorkflowView.vue 增加工具栏、导入弹窗、预览表格和状态管理
API
routes/workflows.py 增加模板、预览、确认接口
业务服务
WorkflowService 负责权限、解析编排、快照校验和提交
解析模块

存储

依赖

导入快照表

建议新增 workflow_task_imports，字段包括：

import_id       TEXT UNIQUE
workflow_key    TEXT NOT NULL
actor           TEXT NOT NULL
filename        TEXT NOT NULL
sheet_name      TEXT NOT NULL
tasks_json      TEXT NOT NULL
preview_json    TEXT NOT NULL
status          TEXT NOT NULL DEFAULT 'previewed'
expires_at      TEXT NOT NULL
created_at      TEXT NOT NULL
confirmed_at    TEXT

快照绑定工作流和操作人，默认 30 分钟过期；确认成功或过期清理。确认接口必须检查工作流、操作人和快照状态。

4. API 契约

5. 任务写入与并发语义

现有状态确认导入时的行为
pending / failed / abandoned更新 type 和 payload，回到 pending
有效租约中的 running跳过，不覆盖执行中的任务
completed默认跳过；超过配置的重跑周期才重新打开
预览后状态发生变化确认时以最新状态重新判断并返回实际统计

服务端应把预览分类逻辑与现有 upsert_workflow_tasks 的状态判断集中到共享方法，避免预览结果和正式导入规则漂移。正式导入必须在同一个 SQLite 事务内完成；数据库异常时整批回滚。

6. 错误处理与安全边界

  • 所有接口沿用工作流管理接口的管理员权限校验。
  • 文件扩展名不是 .xlsx、工作簿损坏、缺少表头、重复表头、超过 5,000 行时，预览失败并返回可读错误。
  • 行级错误只阻止确认，不写入任何任务。
  • 没有有效行时不可确认。
  • import_id 过期、已确认、跨工作流或跨操作人使用时拒绝确认。
  • 确认失败不刷新任务列表；服务端记录文件名、工作流、操作人、统计和失败原因。

7. 测试与验收

  • 解析首个工作表、固定列和 payload 列映射正确。
  • 空行、空 payload、数字/日期等单元格可以稳定转换为 JSON。
  • 缺少 task_key、重复表头、行内重复 key、超过 5,000 行均能在预览阶段发现。
  • 新增、更新、有效 running 跳过、completed 跳过、过期重开符合既有规则。
  • 预览后状态变化时，确认结果以最新数据库状态为准。
  • 确认过程发生数据库错误时，不留下半批任务。
  • 不同工作流/操作人不能复用 import_id，过期快照不能确认。
  • 前端可以下载模板、上传文件、展示逐行错误、禁用错误确认并在成功后刷新列表。
  • 后端 pytest、前端 typecheck/build 均通过。

8. 非目标

  • 首期不支持 .xls、CSV、多工作表选择和字段自定义映射。
  • 不允许 Excel 直接修改 status、租约、尝试次数和完成时间等系统字段。
  • 不改变现有自动获取任务、任务租约和产物处理流程。
