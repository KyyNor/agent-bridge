# 批量 Workflow 运行进度与当前 Run 详情设计

## 状态

- 日期：2026-07-16
- 范围：工作流任务页的前端批量运行体验
- 目标：批量运行时持续看到总体进度，并在同一页面查看当前任务的单次运行详情
- 设计结论：停留在任务页，采用顶部批次进度条 + 页内当前 Run 详情区

## 背景与问题

当前批量运行已经可以按选中任务串行执行：页面调用 `executeWorkflowTask`，拿到 `run_id` 后轮询到终态，再启动下一个任务。队列本身有 `batchProgress`，但页面只把它显示在按钮文字中；执行某个任务时，用户看不到当前 Run 的 Agent 输出、子 Agent 详情和失败上下文，因此批量过程像“卡住了”。

现有单次运行进度页已经具备可复用的能力：`getWorkflowRun` 状态轮询、`listAgentRunsForWorkflowRun`、Agent 事件流、`RunEventTimeline` 和 `SubagentDetailPanel`。本设计优先复用这些能力，不引入独立的后端批次生命周期。

## 目标

1. 批量运行开始后，任务页始终显示批次位置、状态统计和当前任务。
2. 当前任务拿到 `run_id` 后，在任务页内显示与单次运行页同等级别的 Agent 输出和子 Agent 详情。
3. 当前任务完成并切换到下一个任务时，详情区域自动切换到新的 Run。
4. 单项成功、跳过、失败和队列停止都能在批次汇总中明确体现。
5. 保持现有串行执行、并发冲突保护和页面级队列生命周期，不新增后台任务系统。

## 非目标

- 不新增 batch 数据表、批次 API、后台 worker 或服务端持久化队列。
- 不改变单任务执行接口和 workflow run 的状态机。
- 第一版不承诺刷新页面、关闭页面或切换路由后恢复批次。
- 不把批量运行改成并行执行。

## 用户界面

### 1. 顶部批次进度条

任务页工具栏下方增加一个批次状态区域，批量运行时显示：

- `批量运行中 · 当前第 7 / 24 项`
- 进度条，按已完成项计算，例如 `6 / 24`
- 成功、失败、跳过、待执行数量
- 当前任务 key、当前 Run 状态和已运行时间

批量未运行时不占用页面空间。批量结束后保留一条汇总信息，并保留最后一个 Run 的详情，方便用户立即检查结果。

### 2. 当前 Run 详情区

在批次状态区域下方、任务列表上方增加“当前运行详情”卡片。批量运行期间默认展开，包含：

- 当前任务 key、Run ID、状态和开始时间
- 现有 `RunEventTimeline` 的 Agent 输出流
- 多个 Agent run 时的切换入口
- 现有 `SubagentDetailPanel` 的展开详情
- 事件暂时不可用时的非阻塞提示

当前 Run 详情只追踪队列中正在执行的任务，不复制全部任务的日志。任务卡仍保留现有的按任务展开日志能力，二者分别服务于“批次实时观察”和“历史任务检查”。

### 3. 任务卡状态

当前任务卡增加明显的运行中标记；已完成、失败、跳过和排队状态沿用现有 Badge。批量执行的顺序和选择集合仍沿用现有逻辑。

## 运行时数据流

批量队列的执行顺序保持不变，只增加状态回调：

1. 队列启动时复制选中任务，初始化总数、计数器和当前任务为空。
2. `onTaskStart` 设置当前任务，进度显示为“当前第 N 项”，但已完成数不提前增加。
3. `executeWorkflowTask` 返回 `run_id` 后设置当前 Run，并加载该 Run 对应的 Agent runs 与事件流。
4. 等待 Run 终态的轮询同时刷新 `WorkflowRun` 和当前 Agent 事件；事件刷新失败不能阻塞 Run 状态轮询。
5. Run 进入终态后，写入该任务的 success/failed/skipped 结果并更新统计；如果还有下一个任务，则在下一个 Run 启动时替换详情，否则保留最后一个 Run 详情，然后结束队列。
6. 队列完成或停止后显示汇总；若队列停止，保留剩余未执行任务的选择状态。

建议将队列回调扩展为“任务开始、Run 启动、Run 更新、任务结束”四类可选回调。队列库仍负责顺序、取消和停止策略，`WorkflowView` 负责把这些事件映射为 UI 状态。

## 组件与代码边界

- `frontend/capabilities/src/lib/workflowTasks.ts`
  - 保持现有串行队列语义。
  - 增加当前任务 / Run 生命周期回调的类型和触发点。
  - 不承担 Vue 状态，也不直接调用 API。

- `frontend/capabilities/src/views/workflow/WorkflowView.vue`
  - 增加批次统计、当前任务和当前 Run 的响应式状态。
  - 复用现有 `getWorkflowRun`、Agent run 查询和事件轮询逻辑。
  - 批量队列开始、切换、结束时更新状态条和任务列表。

- `frontend/capabilities/src/components/WorkflowRunDetailPanel.vue`
  - 抽取现有单次进度页中的 Agent run 选择、事件时间线和子 Agent 详情展示。
  - 单次运行页和任务页共用该展示组件；数据加载和队列控制仍由父页面负责。

- `frontend/capabilities/tests/`
  - 扩展批量队列纯逻辑测试，验证回调顺序、计数时机、失败继续和停止后的 remaining。
  - 增加当前 Run 状态映射测试，确保事件刷新失败不会改变队列终态判断。

## 错误处理与生命周期

- `executeWorkflowTask` 没有返回 `run_id`：当前任务记为失败，沿用现有队列策略。
- Agent run 查询或事件查询失败：详情区显示降级提示，但继续轮询 `WorkflowRun`，不让展示问题阻塞批量执行。
- Workflow run 失败：详情区保留错误信息，任务计入失败；是否继续由现有 `shouldStopBatchError` 决定。
- 网络错误、并发冲突或页面队列被取消：停止队列，保留未执行任务选择，不静默丢失。
- 路由切换或组件卸载：继续沿用当前 `batchToken` 取消页面级队列的行为。

## 验收标准

1. 选择 3 个任务开始批量运行后，任务页立即显示总数、当前序号、已完成数和待执行数。
2. 当前任务拿到 `run_id` 后，2 秒内出现对应 Agent 事件；事件持续刷新时不需要手动进入进度页。
3. 当前任务结束并开始下一个任务时，详情区和当前任务标记同步切换。
4. 单项失败、跳过和队列停止后的剩余任务数量在汇总中准确显示。
5. 批量结束后可以继续查看最后一个 Run 的事件和子 Agent 详情。
6. 原有单任务执行仍跳转到现有进度页，行为不变。
7. 前端类型检查、批量队列测试和相关组件测试通过。

## 实施顺序

1. 抽取可复用的 Run 详情展示组件，确保现有单次运行页行为不变。
2. 为批量队列增加生命周期回调和更准确的完成计数。
3. 在任务页接入当前 Run 状态、事件刷新和进度条。
4. 增加测试并进行人工验收：成功、失败继续、事件暂时不可用、队列停止和最后 Run 保留。
