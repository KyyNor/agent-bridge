# 知识库上传去重与 ZIP 文档导入设计

## 目标

1. 同一个知识库中，上传内容与现有文档当前版本完全相同的文件时跳过，不创建新的逻辑文档、版本或同步任务。
2. 文件名相同但内容不同的文件继续使用现有全局 slug 重命名规则，例如 `guide`、`guide-2`、`guide-3`。
3. 支持上传 `.zip`：安全递归读取压缩包内的子目录，只导入当前支持的实际文档，忽略图片、脚本和嵌套 ZIP。

## 行为约定

- 内容指文件字节内容，使用现有归档层计算的 SHA-256，不使用 MD5。
- 去重范围是目标知识库，不是全局；同一文件可以分别加入不同知识库。
- 普通文件上传仍返回原有单文档对象；重复时在对象上增加 `skipped: true` 和 `skip_reason: "duplicate_content"`。
- ZIP 上传返回汇总对象，包含成功导入的 `documents`、跳过的 `skipped`、`uploaded_count` 和 `skipped_count`。
- ZIP 中没有可识别文档、压缩包损坏、路径穿越或读取校验失败时，整包失败，不创建其中任何文档。
- ZIP 内的文件按归档成员路径排序后处理；实际文档使用文件名作为显示名，目录路径不写入文档名。相同文件名仍由现有 slug 规则重命名。

## 架构

### 服务层

`AgentBridgeService.add_document` 保持普通文件调用兼容，并根据来源后缀分派：

- 普通文件走单文件入库流程。
- ZIP 先调用独立的安全解压辅助模块，把实际文档落到临时目录，再逐个调用单文件入库流程。
- 单文件流程先计算 SHA-256，在目标知识库中查找当前版本相同的文档；命中则复用已有文档并跳过新增。若同一调用包含多个目标知识库，则把已有文档补挂到尚未关联的目标知识库并只为这些目标创建同步任务。
- 未命中时沿用现有 `unique_slug(make_slug(...))`、归档、版本和 `Operation.create` 同步任务流程。

### 安全 ZIP 解压

新增文档上传辅助模块，使用 `zipfile.ZipFile`：

- 拒绝绝对路径和包含 `..` 的成员路径。
- 忽略目录、符号链接、嵌套 ZIP 以及不在 `ALLOWED_EXTENSIONS` 中的文件。
- 先校验归档成员并完整读取校验，再解压支持的文件，避免已经导入部分文档后才发现压缩包损坏。
- 所有临时文件位于临时目录，单次请求完成后自动清理。

### 前端

- 上传选择器和拖拽过滤增加 `.zip`。
- 上传完成后根据 API 汇总显示导入数量和跳过数量。
- 上传失败时在对话框中显示服务端错误，便于识别损坏 ZIP 或空 ZIP。

## 测试范围

- 同一知识库同内容重复上传只保留一个文档和一组创建同步任务。
- 同内容上传到不同知识库不会误跳过。
- 同名不同内容仍生成 `-2` slug。
- ZIP 可递归导入支持文档，忽略不支持文件、嵌套 ZIP 和符号链接。
- ZIP 内重复内容只导入一次，同名不同内容保留并重命名。
- 损坏 ZIP、路径穿越 ZIP、无支持文档 ZIP 均不产生文档。
- 前端 ZIP 选择、结果汇总类型、类型检查和生产构建通过。
