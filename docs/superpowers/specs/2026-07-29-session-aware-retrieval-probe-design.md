# 会话感知的 full-probe 关键词提取设计

## 目标

将 full-probe 的关键词输出范围从 2–8 改为 0–8。服务端按 Claude Code 提供的
`session_id` 保存提示词和模型提取结果，并在每次请求时给模型提供此前最多 3 轮记录，
使模型只返回本轮新增的检索短句；没有新增信息时返回空数组。

当前仍只检索当前 Profile 的工作流产物。模型超时、未配置、网络失败或输出无效时保持
fail-closed，不做产物检索，也不写入会话历史。

## 存储方案

使用 DiskCache 而不是 SQLite 表：数据是短生命周期会话状态，读取频繁、无需管理界面查询，
且需要跨服务重启保留。缓存根目录位于 `AgentBridgePaths.data_dir` 下的
`retrieval-probe-sessions/`。

缓存键为由 `profile_key` 和 `session_id` 明确编码得到的复合键，避免不同 Profile 的会话
相互读取。值是按时间升序的记录列表：

```json
{
  "entries": [
    {
      "prompt": "轮次 1 提示词",
      "keywords": ["xx", "yy"],
      "created_at": "2026-07-29T00:00:00+00:00"
    }
  ]
}
```

每个 session 保留最近 12 条成功模型结果，使用常量
`SESSION_HISTORY_RETAINED_ROUNDS = 12`。当前构造模型上下文时仅读取最近 3 条，使用
`SESSION_HISTORY_PROMPT_ROUNDS = 3`；两者分离，未来扩大上下文不需要改变缓存格式。

缓存使用滑动 30 天 TTL：每次成功模型提取（包括有效的空数组）写回时重置过期时间。
模型失败、超时、未配置和输出无效都不改变缓存。缺少 `session_id` 时照常进行单轮模型
提取，但不读写缓存。

## 提取流程

```text
收到 prompt 和 session_id
  -> 读取本 Profile/session 最近 3 条缓存记录
  -> 构造“历史轮次 + 本轮提示词”模型输入
  -> 模型受 JSON Schema 约束输出 0–8 个短句
  -> 服务端校验/过滤
  -> 成功（包括 []）写入最近 12 条历史并续期 30 天
  -> 仅对过滤后的非空短句检索工作流产物
```

模型提示词明确标出每轮的提示词和既有提取结果，并要求：输出仅含本轮新增、可直接检索的
原始业务短句；不得重复历史结果；没有新增时返回 `{"keywords":[]}`。

OpenAI SDK 的 `structured_outputs.json_schema` 将 `keywords` 的 `minItems` 改为 0、
`maxItems` 保持 8。

## 服务端二次校验

模型结构化输出不是唯一防线。服务端在写缓存和检索前执行：

- 严格解析仅含 `keywords` 的 JSON 对象，允许 0–8 项；
- 去首尾空白、按大小写无关的规范化键去重并保留原顺序；
- 过滤空值、停用词、单字、过长项和非字符串；
- 过滤与最近 3 轮历史关键词规范化后完全相同的项；
- 任意结构错误或非法项使本轮输出无效，按既有 fail-closed 处理；
- 有效空数组是正常成功结果：写入缓存、返回成功、但不产生 Artifact 检索任务。

“语义重复”由模型提示词负责，服务端只做可确定的文本规范化重复过滤，避免凭规则错误地
删除不同业务术语。

## 组件与可观测性

新增独立 `ProbeSessionHistoryStore` Protocol 和 DiskCache 实现；关键词抽取器依赖该
Protocol，不直接依赖缓存库。应用装配时从 `AgentBridgePaths` 创建 store 并注入提取器。

`KeywordExtraction` 增加可公开的历史信息，如已使用的历史轮数和被服务端过滤的数量；不
在响应、日志或审计中暴露历史提示词全文。现有原始 Hook payload 审计继续按既有权限保存。

关键日志记录 session 是否可用、历史轮数、返回/过滤后的关键词数量、缓存写入结果和耗时；
日志不得记录 API Key 或结构化模型原始输出。

## 测试

- 0 项和 8 项关键词均可通过，9 项或不合法结构失败。
- 第 4 轮请求只向模型提供最近 3 轮；缓存仍保留最近 12 轮。
- 空数组写入历史并续期；超时、未配置和无效输出不写缓存。
- 当前输出与历史完全重复时被过滤，过滤后为空时不调用 ArtifactProbeAdapter。
- session ID 缺失时不访问缓存，仍能单轮提取。
- Profile 不同但 session ID 相同不会共享历史。
- DiskCache TTL、重启后可读、过期后不可读，以及并发读写行为均有测试。
