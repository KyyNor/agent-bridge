能力平面配置二级详情页设计

日期：2026-07-16　·　范围：frontend/capabilities　·　状态：已获用户确认，待实施

目标：将能力平面配置从小尺寸弹窗改为类似知识库的 hash 二级详情页，并让“取消 / 确认”始终可见。当前配置字段、API 和业务语义保持不变。

1. 已确认的交互方向

  • 采用 A 方案：完整详情页，而不是左右分栏或大尺寸侧滑面板。
  • 列表路由为 #profiles，详情路由为 #profiles/<profile_key>。
  • 顶部返回、底部取消和浏览器后退在存在未保存修改时，都要先确认“放弃未保存修改”。
  • 确认放弃后返回能力平面列表；取消放弃则恢复详情页并保留编辑内容。
  • 添加能力平面仍使用小弹窗；只有已有能力平面的配置改为详情页。

2. 页面与组件结构

位置职责变化
App.vue 读取复合 hash，并将 subRoute 传给能力平面页面。 改为渲染 <ProfilesView :route-key="subRoute" />。
lib/navigation.ts 决定详情页是否显示顶层页面标题。 把 profiles 纳入二级路由隐藏页面标题的集合。
ProfilesView.vue 列表页、添加弹窗和路由控制器。 接收 routeKey；“配置”改为进入详情 hash；处理返回、取消、浏览器后退和列表刷新。
新增 ProfileDetailView.vue 加载并编辑一个能力平面的完整配置。 承接现有配置弹窗的状态、API 调用和表单内容，暴露未保存状态给路由控制器。

详情组件通过 profileKey 接收当前 key，发出 saved、back、cancel 等事件。路由控制器统一决定何时把 hash 切回 #profiles，避免组件直接修改列表状态。

3. 详情页布局

  1. 顶部使用知识库详情页同款返回区：返回按钮、能力平面名称、profile_key、描述和状态 Badge。
  2. 中间内容按现有配置顺序展示：接入命令、记忆、允许访问的服务、文档知识、代码仓库、高级选项。
  3. 详情根容器采用全高 flex 布局；中间内容区设置 min-h-0 和 overflow-y-auto，长列表和高级选项只在主体内滚动。
  4. 底部操作区位于主体滚动区之外，使用边框和背景与内容区分隔，始终展示“取消 / 确认”。
  5. 保存中禁用重复保存和离开；保存错误显示在操作区上方，不能因为滚动位置导致用户看不到。
  6. 移动端保持纵向堆叠，服务、知识库和代码仓库选择器继续使用现有响应式宽度。

4. 数据流与保存行为

加载

进入详情后并行加载能力平面完整配置、能力目录、文档知识、代码仓库和记忆绑定；Pin 预览与 Profile 文档继续按现有异步流程加载。核心配置失败时显示整页错误；非核心资源失败时保留页面，并在对应区块显示错误。

本地编辑与局部保存

沿用当前 pendingRules、pendingResources、pendingMemoryBlock、Pin 和 Notes 状态。现有“保存 Pin”“保存手动补充”“重新生成/预览”等局部操作保留，成功后同步更新初始快照，避免保存后仍被误判为未保存。

底部确认

底部“确认”复用当前保存顺序：保存服务规则、资源规则、已加载的 Pin 配置、记忆绑定，刷新 Profile 文档并刷新列表。任何一步失败都停留在详情页，保留用户当前待保存值并展示错误。

5. 未保存保护

hasUnsavedChanges 比较进入详情时的初始快照和当前编辑值，至少覆盖：

  • 服务允许规则和文档/代码资源规则；
  • 记忆绑定；
  • 手动 Pin、自动 Pin 模式、比例和数量；
  • 尚未提交的手动 Notes。

顶部返回与底部取消调用同一离开保护函数。浏览器后退导致详情 routeKey 被清空时，路由控制器先恢复详情状态并弹出确认；用户确认放弃后再完成列表导航，取消则停留在详情页。

6. 非目标与兼容性

  • 不新增后端接口，不改变能力平面配置的 API 契约。
  • 不改动添加能力平面、启停、复制命令和列表筛选分页的业务行为。
  • 不在本次范围内重做配置字段、Pin 规则或 Profile 文档的业务模型。

7. 验收与测试

  • #profiles/<key> 能直接打开详情，顶层“能力平面”页面标题隐藏。
  • 列表“配置”进入详情；顶部返回无修改时直接回列表。
  • 修改任一配置后，顶部返回、底部取消和浏览器后退都会触发放弃确认。
  • 取消放弃时编辑内容保留；确认放弃后回到列表。
  • 详情内容很长时，底部“取消 / 确认”仍保持可见。
  • 加载核心配置失败、Pin/记忆/文档加载失败、保存失败均有可见反馈。
  • 保存成功后回到列表，列表状态刷新。
  • 运行前端单元/源码结构测试、npm run typecheck 和 npm run build。
