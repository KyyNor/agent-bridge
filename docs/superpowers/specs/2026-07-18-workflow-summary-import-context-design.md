# 工作流总结导入与任务上下文设计

## 目标

修复工作流导入后节点输出 Schema 不一致、Agent/总结提示词缺少任务信息的问题，并让总结类工作流导入时自动维护末尾两个系统输出节点。

## 设计

### 任务上下文

Agent 和 Output 节点统一使用工作流运行上下文生成任务说明块，包含任务 key、任务版本、任务类型和 payload。该说明块只在当前运行已经领取任务时注入；显式的 `{{ task... }}` 模板继续保留并照常渲染。Markdown 总结节点在任务说明之后继续附加全部祖先节点输出，HTML 节点继续只消费 Markdown 主产物。

### 总结类导入

`workflow_type=summary` 的导入在定义校验前进行规范化：保留业务节点，识别已有的总结输出，转换或生成 `summary_markdown` 与 `summary_html` 两个系统节点，将所有业务末端节点连接到 Markdown 节点，并补充唯一的 Markdown → HTML 无条件系统边。系统节点位于节点列表末尾，普通输出节点不作为总结末端节点保留；若存在多个无法判定的普通输出节点，导入返回明确错误。

### Schema 展示

沿用现有节点面板的“输出模式 / JSON Schema”展示机制，不增加新的编辑器。Agent 继续展示自身 JSON Schema；Script 根据已选择托管脚本展示其输出 Schema；get_task 和 Output 使用固定输出契约展示；文本 Agent 展示文本输出契约。引用选择器继续从同一份契约派生字段。

## 验收

- Agent 与 Output 提示词包含当前任务说明，并且仍支持显式任务模板。
- 总结节点同时获得任务说明和上游输出。
- 只有一个普通 Markdown 输出的总结导入会转换该节点并自动生成 HTML 系统节点。
- 无输出节点的总结导入会自动生成两个系统节点。
- 总结导入后的图满足现有末端顺序、系统边和依赖约束。
- 节点面板能看到 Agent、Script、get_task、Output 的有效输出契约。
