文档知识目录化设计

在 Agent Bridge 中为文档知识库增加本地目录树，并按后端能力选择是否同步远端目录层级。

状态：设计已确认 范围：文档管理、展示、同步 暂不做：目录级权限、目录级检索隔离

1. 背景与目标

当前系统已经在数据库层支持一个文档关联多个知识库，但前端上传和列表展示仍然是单知识库、单层级平铺。目标是在不破坏现有知识库检索语义的前提下，把文档组织为目录树，并让支持目录的后端保留该层级。

核心决策：本地目录树是规范数据源；目录关系挂在 document_kbs 文档-知识库关联上，而不是挂在全局 documents 记录上。这样同一文档在不同知识库中可以位于不同目录。

目标行为

  • 本地知识库不再默认把所有文档平铺展示，而是通过目录树管理。
  • 本地根目录是虚拟节点，不进入同步路径。
  • 本地 A/B/guide.pdf 同步到支持目录的后端时仍是 A/B/guide.pdf。
  • 不支持目录的后端继续把文件上传到后端知识库根目录。
  • 删除目录时递归删除当前知识库中的目录和文档关联，并在执行前展示目录数和文件数。

2. 当前系统事实与边界

  • documents 是全局文档实体，document_kbs 是文档与知识库的多对多关联。
  • 后端 API 已能在一次上传中把一个文档关联到多个知识库，但当前前端只传入一个知识库。
  • 当前删除接口是全局文档级操作；目录化必须增加知识库关联级删除，避免删除共享文档时影响其他知识库。
  • 当前上传流程会丢失浏览器文件夹的相对路径，ZIP 解压后也只把文件名传入文档入库流程；两者都需要改为保留相对目录。
  • Git 数据源当前按文件名导入，未保留仓库相对目录；目录化后应以仓库相对父路径作为本地目录。
不在本次范围内：目录级 Profile 权限、目录级检索范围、跨知识库目录共享、目录标签与收藏。默认检索仍覆盖整个知识库。

3. 本地数据模型

knowledge_bases
  └── knowledge_folders
        ├── folder_id
        ├── kb_id
        ├── parent_id
        └── name

documents ──< document_kbs >── knowledge_folders

3.1 knowledge_folders

字段含义
id稳定的本地目录 ID。
kb_id所属知识库。
parent_id父目录；每个知识库只有一个根节点，根节点的父 ID 为空。
name目录名称。相同父目录下不允许重名。
sort_order目录树展示顺序。
created_at / updated_at审计与排序时间。

目录路径不作为主键。重命名或移动目录只更新父子关系和展示路径，不改变文档 slug、版本和内容寻址归档。

3.2 document_kbs.folder_id

为 document_kbs 增加 folder_id。逻辑上每条活动关联都必须有目录；迁移阶段先以可空字段加入并回填，再由存储层保证所有新增或更新关联都写入有效目录。

该字段使以下场景成立：

  • 文档 X 在知识库 A 的 前端/组件 下。
  • 文档 X 在知识库 B 的 公共资料 下。
  • 删除 A 中的文档关联不会删除 B 中的关联。

3.3 后端目录映射

新增后端目录映射表，至少保存 kb_id、backend_slug、folder_id、backend_folder_id、path_snapshot 和状态。只为真正支持目录的后端创建映射，当前主要用于 WeKnora。

4. 根目录与路径语义

本地数据库保留根目录记录是为了让目录树、文档关联和 API 都拥有统一的父节点，但根目录不是用户同步路径的一部分。

本地表达同步路径说明
根目录下的文件后端知识库根路径为空。
A/guide.pdfA/guide.pdf顶层目录 A 直接对应远端顶层目录。
A/B/guide.pdfA/B/guide.pdf不产生额外的“根目录”路径段。

前端可以把根节点显示为知识库名称，把“全部文档”作为快捷筛选；“全部文档”不是目录，也不会生成远端节点。

5. 后端同步能力

后端本次分类行为
WeKnora支持目录创建或复用远端目录，文件上传到对应目录；移动文档时同步远端位置。
PageIndex不支持目录本次按知识库平铺同步，不接入其闭源/付费产品的文件夹能力。
RAGFlow不支持知识库内目录本次继续使用 dataset 文档上传，文件在远端知识库内平铺。
Mock不支持目录保持现有平铺行为。

RAGFlow 官方资料区分了全局文件管理器和知识库目录：文件管理器可以使用嵌套文件夹，但知识库对应目录内部不能创建子目录，因此不满足本项目“每个知识库独立保留目录树”的语义。参见 RAGFlow 文件管理文档。

PageIndex 官方 JavaScript SDK 文档确实描述了嵌套文件夹和 folderId，但该能力标注为 Max 计划；本项目本次明确不接入这一能力，当前适配器按平铺后端处理。参见 PageIndex 文件夹文档。

5.1 适配器契约

通用同步服务只依赖后端能力声明，不把 WeKnora 的接口细节写进服务层：

BackendCapabilities(
    supports_folders: bool,
)

ensure_folder_path(backend_kb_id, path_parts) -> remote_folder_id
upload(..., remote_folder_id=None) -> remote_doc_id
move_document(..., remote_folder_id) -> None
delete_remote_folder(..., remote_folder_id) -> None
  • WeKnora 实现目录创建、目录复用、上传到目录和文档移动。
  • PageIndex、RAGFlow、Mock 声明 supports_folders=false，服务层不调用目录接口。
  • 不支持目录的后端仍接收普通上传参数，目录参数被忽略，保持兼容。
  • WeKnora 的目录接口失败时，同步任务标记失败并保留错误；不自动改为平铺上传。

6. 上传、移动与同步数据流

1. 本地入库解析目录路径，创建缺失目录，把文档关联到目标 folder。
2. 生成任务按知识库已有后端目标创建同步任务，记录目标目录上下文。
3. 后端执行WeKnora 确保远端路径后上传；其他后端直接上传到知识库根。

上传来源

  • 单文件上传：使用当前选中的目录。
  • 浏览器文件夹上传：使用每个文件的 webkitRelativePath，以当前目录为基准创建相对子目录。
  • ZIP 上传：保留 ZIP 成员的相对路径，安全校验后创建对应子目录。
  • Git 数据源：使用仓库根目录到文件的相对父路径作为目录路径；现有 Git 文档在下一次同步时补齐目录。

移动文档

  • 本地先更新 document_kbs.folder_id。
  • 取消同一关联上尚未执行的旧位置任务，生成新的移动任务。
  • WeKnora 执行远端移动；平铺后端不生成移动任务，因为远端文件位置不变。

7. 删除语义

7.1 目录删除

根目录不可删除。普通目录递归计算子目录数和当前知识库中的活动文档关联数，确认对话框显示：

你删除的目录下有 N 个目录、M 个文件，确认删除后都将被删除且无法恢复。

确认后：

  1. 递归删除目录树中的当前知识库目录记录。
  2. 删除当前知识库与这些文档的关联。
  3. 为当前知识库的远端文档生成删除任务。
  4. 共享文档如果仍属于其他知识库，只保留其他知识库的关联、目录和远端文档。
  5. 文档不再属于任何知识库时，才执行全局文档删除、归档清理和所有远端删除。
  6. WeKnora 中已空的目录映射按需清理。

7.2 API 语义

新增按知识库关联删除的服务方法，不能继续直接复用当前按全局 doc_slug 删除的路径。当前全局删除接口保留给真正不再被任何知识库引用的文档清理流程。

8. API 与前端交互

8.1 API

GET    /kbs/{kb_slug}/folders
POST   /kbs/{kb_slug}/folders
PATCH  /kbs/{kb_slug}/folders/{folder_id}
DELETE /kbs/{kb_slug}/folders/{folder_id}

GET    /docs?kb={kb_slug}&folder_id={folder_id}
POST   /docs                         + folder_id / relative_path
PATCH  /docs/{doc_slug}/placement
POST   /docs/{doc_slug}/attach       + target kb / folder
  • 未传 folder_id 的旧文档列表接口保持兼容，返回该知识库全部文档。
  • 文档列表响应增加 folder_id 和 folder_path。
  • 目录树响应提供后代文件总数，便于前端展示和删除确认。
  • 目录操作都校验目录属于目标知识库，并拒绝移动到自身或后代目录。

8.2 页面

知识库列表页移除“上传”按钮。上传必须从知识库详情页发起，以确保有明确的目录上下文。

详情页使用“左侧目录树 + 右侧文件列表”：

  • 根节点显示知识库名称；“全部文档”是快捷筛选，不是同步路径。
  • 右侧面包屑显示当前目录。
  • 目录工具栏提供新建、重命名、移动和删除。
  • 上传默认进入当前选中目录；进入详情页默认选中根目录。
  • 文件列表提供移动到目录、关联到其他知识库/目录和当前知识库关联删除。
  • WeKnora 显示“目录同步”；其他后端显示“本地分目录，后端平铺”。

9. 数据迁移与兼容

  1. 为每个现有活动知识库创建唯一根目录。
  2. 为现有 document_kbs 关联增加字段并回填到对应根目录。
  3. 所有旧文档默认位于知识库根目录，不改变文档 slug、版本、内容 hash 和远端文档 ID。
  4. 旧的单文件上传请求未传目录时自动落到根目录。
  5. 前端列表页上传入口删除，旧的详情页上传流程改为根目录上传。
  6. 现有 Git 文档首次目录化同步时根据仓库相对路径补齐目录，并生成移动/更新任务。
  7. 已有后端目标不支持目录时不创建目录映射，继续复用现有平铺同步。

10. 错误处理与安全边界

  • 目录名称不能为空，拒绝路径分隔符、路径穿越片段和控制字符。
  • 创建目录和移动目录时校验同级重名及循环引用。
  • ZIP 路径继续执行绝对路径、..、符号链接和嵌套压缩包校验。
  • WeKnora 目录创建失败时，任务进入失败状态并可重试；不隐藏失败或偷偷平铺。
  • 目录删除确认前后都按当前知识库关联重新计算，避免确认期间数据变化导致误删。
  • 共享文档的归档文件只有在最后一个知识库关联删除后才清理。

11. 测试与验收

后端与存储

  • 旧数据库迁移后每个知识库有根目录，所有旧关联落在根目录。
  • 同一知识库目录树支持创建、重命名、移动、同级重名校验和循环移动拦截。
  • 同一文档可在不同知识库关联到不同目录。
  • 删除目录会递归计算数量，并只删除当前知识库关联；共享文档在其他知识库中仍可见。
  • 删除最后一个关联后才清理全局文档和归档。
  • 单文件、浏览器文件夹、ZIP、Git 数据源均保留正确相对目录。

后端适配器

  • WeKnora：目录创建复用、上传到目录、移动文档、目录失败重试。
  • RAGFlow、PageIndex、Mock：不调用目录接口，文件仍平铺上传。
  • 不同后端同一文档可以分别拥有自己的同步位置和同步状态。

前端

  • 知识库列表页不再显示上传按钮。
  • 详情页目录树、面包屑、根目录上传和子目录上传正常工作。
  • 目录删除确认准确显示后代目录数和文件数。
  • 类型检查和生产构建通过。

12. 实施顺序

  1. 数据库迁移、目录 repository 和目录服务。
  2. 文档关联级目录字段、上传路径解析、移动和删除语义。
  3. 后端同步任务与 WeKnora 目录适配；平铺后端兼容处理。
  4. 目录 API 与前端目录树、详情页上传。
  5. 移除列表页上传入口，补齐错误提示、同步状态和测试。
完成定义：本地目录树成为文档管理的主入口；WeKnora 保留目录层级；RAGFlow、PageIndex、Mock 保持远端平铺；共享文档删除不会误伤其他知识库。
