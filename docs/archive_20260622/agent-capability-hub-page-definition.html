1. 页面设计原则

这是一个偏运维和治理的内部平台，界面应该克制、清晰、密度适中。

Principles

先展示可用能力

首页和列表页要让用户马上看到已接入多少 MCP 服务、多少工具、哪些服务异常，而不是营销式介绍。

登记流程要确定

新增 MCP 服务的表单需要清楚区分必填配置、认证 headers、连接测试和工具同步结果。

为 Agent 使用而写

工具详情页不仅给人看，也要帮助管理员写出适合 Agent 检索和调用的描述、标签、示例。

2. 信息架构

侧边导航建议先按“概览、MCP 管理、MetaMCP、治理预留、系统设置”组织。

Navigation
导航 页面 阶段 用途
概览 平台概览 一期 查看服务数量、工具数量、异常服务、最近同步状态。
MCP 管理 MCP 服务列表、服务详情、新增/编辑服务、工具详情 一期 登记 HTTP MCP 服务、同步工具、维护工具元数据。
MetaMCP MetaMCP 接入说明、search/execute 契约、search 路径浏览示例 一期 告诉使用者如何接入统一网关，以及如何构造 search/execute。
调用记录 调用日志、日志详情 预留 后续查看 search 和 execute 的调用、耗时、错误和响应样例。
访问策略 Project Profile、服务白名单/黑名单 预留 后续按项目或场景控制服务和工具可见性。
操作治理 Action 工具治理、风险等级、审批配置 预留 后续让有副作用工具可控进入平台。

3. 一期页面定义

以下页面建议进入第一版设计稿，并作为一期实现优先级。

Phase 1
页面 核心区块 关键交互 设计注意
平台概览 服务数、工具数、启用服务数、同步失败数；最近同步列表；快速新增服务按钮。 点击异常服务进入详情；点击新增服务打开登记页。 首页要像运维控制台，突出状态和待处理项。
MCP 服务列表 搜索框、标签筛选、状态筛选、服务表格、工具数量、最近同步时间。 新增、编辑、启停、测试连接、同步 tools、进入详情。 表格密度适中；状态要明显区分 enabled、disabled、error、syncing。
新增/编辑 MCP 服务 基础信息、连接配置、认证 headers、标签、描述、启用状态。 测试连接、保存、保存并同步 tools。 headers 可用键值对编辑器；敏感值支持遮罩展示。
MCP 服务详情 服务信息、连接状态、同步状态、工具列表、错误信息、操作区。 同步 tools、编辑服务、启停服务、进入工具详情。 详情页上半部分展示服务健康和同步信息，下半部分展示工具清单。
工具详情 工具名称、描述、input schema、工具类型、标签、调用示例、是否可执行。 编辑展示描述、标签、工具类型、示例；保存平台侧覆盖信息。 schema 展示要清晰，示例要可直接复制给 execute 使用。
MetaMCP 接入说明 服务地址、search 路径浏览规则、execute 参数、示例、错误码。 复制配置、复制 search/execute 调用示例。 这是给 Agent 使用者看的说明页，应突出 search 像 ls 一样浏览能力目录。

4. 未来预留页面

这些页面可以先出设计稿，但不作为一期开发验收。

Future

调用日志

展示 search/execute 的调用入口、服务、工具、参数校验、耗时、成功状态、错误信息和响应样例。

  • 列表筛选：时间、服务、工具、成功状态、调用入口。
  • 详情区块：请求参数、匹配结果、远端响应、标准化错误。
  • 设计稿可先保留，不进入一期功能。

Project Profile

按项目或场景定义可见 MCP 服务和工具范围，用于 Claude Code 或其他 Agent 接入时携带 profile。

  • 列表：profile 名称、描述、允许服务、屏蔽服务。
  • 详情：白名单、黑名单、默认策略、绑定项目。
  • 一期只在信息架构中预留。

操作类工具治理

用于二期开启 action 工具执行，包括风险等级、二次确认、dry-run、审批和强审计。

  • 工具风险分级：低、中、高、禁止。
  • 执行策略：不可执行、需确认、需审批、允许 dry-run。
  • 一期 action 只允许登记和搜索。

能力评测

后续对工具描述、参数示例、调用成功率、检索命中率做运营评估。

  • 测试问题集、命中率、失败率、平均耗时。
  • 工具说明缺失、schema 不清晰、示例不可用的提示。
  • 适合三期以后建设。

5. 关键组件定义

组件应该支持未来页面复用，避免每个页面重新设计同类信息。

Components
组件 用途 内容
Service Status Badge 展示 MCP 服务状态。 enabled, disabled, error, syncing, unknown。
Tool Type Badge 展示工具类型。 overview, search, detail, action；action 使用警示色。
Schema Viewer 展示 input schema。 字段名、类型、是否必填、描述、默认值；支持 JSON 原文折叠。
Header Editor 编辑 HTTP MCP 认证 headers。 键值对表格、敏感值遮罩、新增/删除行。
Example Block 展示 search/execute 示例。 代码块、复制按钮、服务和工具上下文；search 示例必须覆盖空参数、query、path、path + query 四种场景。

6. 页面状态

设计稿需要覆盖空状态、错误状态和同步中状态，避免页面只适合演示数据。

States

空状态

没有 MCP 服务时，首页和列表页展示“新增第一个 MCP 服务”的主按钮，并提示当前仅支持 HTTP MCP。

连接失败

服务详情页展示失败原因、最近测试时间、重试按钮和编辑连接配置入口。

同步中

同步 tools 时列表行和详情页显示进度状态，避免重复触发同步。

7. 给前端设计的交付要求

设计稿可以先完整，但实现范围按阶段一裁剪。

Handoff
  1. 优先设计桌面端，移动端只需保证基础可用，不追求复杂管理操作的移动体验。
  2. 页面风格应偏内部控制台：清楚、克制、可扫描，不做营销页。
  3. 一期页面必须出高保真：平台概览、MCP 服务列表、新增/编辑服务、服务详情、工具详情、MetaMCP 接入说明。
  4. 预留页面可以出中保真：调用日志、Project Profile、操作类治理、能力评测。
  5. 所有表单需要给出默认、加载、错误、成功、禁用状态。
  6. 工具 schema、search 路径浏览示例和 execute 示例是核心设计对象，不能只用普通文本块糊过去。
