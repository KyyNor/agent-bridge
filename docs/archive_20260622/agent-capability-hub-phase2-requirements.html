1. 阶段定位

阶段二不急着开放有副作用 action 工具，而是先让平台“可诊断、可统计、可管理内置知识/代码能力”。

Decision
一句话目标： 管理员可以从日志和统计中判断调用失败归因、服务质量和 Profile 使用趋势；项目可以通过 Profile 绑定外部 MCP、Wiki KB 和 CodeGraph 仓库；模型通过稳定的 MetaMCP 入口查询代码仓库与知识库，但不能绕过 Profile 访问未授权资源。

本阶段优先解决

  • 失败原因不可区分：平台解析失败、策略拦截、MCP 连接失败、上游工具失败需要分开统计。
  • 日志请求/响应难读：列表里只放摘要，详情通过浮窗展示完整 JSON。
  • 缺少运营视角：按 profile、service、tool、组合维度看调用趋势、失败率和耗时。
  • Wiki 与 CodeGraph 不应作为普通可关闭 MCP 服务，而应成为平台固有能力。

设计约束

  • 沿用当前 FastAPI HTML shell + static CSS/JS，不引入前端构建链。
  • 延续内部可信环境策略，敏感字段脱敏和企业密钥治理预留接口。
  • Project Profile 继续由服务端强制执行，页面和 CLI 只负责配置与预览。
  • 内置工具不可在 Profile 中被直接关闭，只能限制可查阅资源。

明确不做

  • 不开放 action 类工具执行、审批、二次确认和 dry-run。
  • 不做 OpenAPI 导入、CLI runner、脚本执行市场。
  • 不做完整企业权限、组织空间、配额和账单。
  • 不做复杂 BI 系统；统计页面先满足排查和趋势判断。

4. 日志分析需求

现有日志已经记录 request、response、status、duration；本阶段重点是让失败归因可筛选、可统计、可阅读。

Observability

失败归因字段

  • failure_stage：失败发生阶段，例如平台解析、Profile 策略、注册表校验、MCP 传输、MCP 协议、上游工具、内部异常。
  • failure_owner：归因对象，例如 platform、policy、upstream_mcp、builtin_backend。
  • error_type：稳定错误类型，供筛选和统计使用。
  • error_message：人类可读错误，不作为统计主键。
  • upstream_status：目标 MCP 或内置后端返回的协议状态、HTTP 状态或解析状态。
错误类型 含义 归因
platform_request_parse_error MetaMCP 入参 JSON、path、schema 或工具参数在本项目内解析失败。 platform
profile_policy_blocked profile 不存在、已停用、服务或资源被策略拦截。 policy
capability_registry_error service、tool、KB 或 repository 不存在、禁用或未配置。 platform
mcp_transport_error 目标 MCP 连接失败、超时、握手失败、streamable HTTP 会话失败。 upstream_mcp
mcp_protocol_error 目标 MCP 返回不符合协议、list_tools/call_tool 异常。 upstream_mcp
upstream_tool_error MCP 工具被成功调用，但工具自身返回失败或异常。 upstream_mcp
builtin_backend_error Wiki 后端、CodeGraph 同步或查询后端失败。 builtin_backend
internal_error 未被分类的本项目异常。 platform

日志列表筛选

  • 时间范围：最近 1 小时、24 小时、7 天、30 天、自定义。
  • 入口：metamcp_search、metamcp_execute、raw_mcp、wiki、codegraph。
  • Profile、source type、服务/内置能力、工具名、状态。
  • 失败阶段、错误类型、归因对象、耗时区间。
  • 关键词：log_id、source_key、tool_name、error_message。

请求/响应浮窗

  • 列表中请求和响应只展示摘要、大小、是否截断和关键参数。
  • 点击“查看”打开浮窗，分 Tab 展示请求、响应、错误、耗时链路。
  • JSON 自动格式化，支持折叠长字段、复制完整 JSON、复制 log_id。
  • 超大 payload 后续按 max_payload_bytes 截断，浮窗明确标记截断状态。

5. 统计页面需求

统计页面用于定位“哪个 profile、服务、工具或组合维度正在失败、变慢或调用量异常”。

Analytics

核心指标

  • 调用量、成功数、失败数、拦截数。
  • 失败率、拦截率、成功率。
  • 平均耗时、P50、P95、最大耗时。
  • 错误类型 Top N、慢调用 Top N。

维度

  • Profile、entrypoint、source_type、service/source_key、tool_name。
  • 内置资源：repo_key、kb_slug。
  • 状态、失败阶段、错误类型、归因对象。
  • 组合维度：profile + service、profile + tool、service + tool。

交互

  • 时间粒度：小时、天。
  • 快捷时间：24 小时、7 天、30 天。
  • 点击统计行跳转到日志页，并自动带上对应筛选条件。
  • 轻量趋势图可以使用 CSS/SVG，不要求引入图表框架。
视图 内容 价值
总览 总调用、失败率、P95、Top 失败来源、Top 慢工具。 快速判断系统整体健康度。
Profile 趋势 每个 profile 的调用量、失败率、拦截率和耗时趋势。 判断项目接入是否配置异常或使用量突增。
服务/工具趋势 按 MCP service、内置能力和 tool 统计成功、失败、耗时。 定位具体服务或工具的稳定性问题。
错误分布 按 failure_owner、failure_stage、error_type 聚合。 区分平台问题、策略问题、上游 MCP 问题和内置后端问题。

6. Project Profile 增强

Profile 从“外部 MCP 服务访问规则”扩展为“项目可见能力与资源范围”。

Profile

复制接入命令

  • Profile 列表和详情页增加“复制接入命令”按钮。
  • 按钮弹出命令预览浮窗，默认使用当前页面 origin 推导 /mcp URL。
  • 命令包含 --profile，但可以不包含 --scope，让 CLI 交互式选择项目级或用户级。
  • 同时保留高级选项：直接复制项目级命令、直接复制用户级命令。
wiki metamcp add --url http://127.0.0.1:8765/mcp --profile safe-readonly

CLI 交互

  • --scope 缺省时提示选择：当前项目、当前用户。
  • 非交互环境下缺少 --scope 应报错并提示可用参数，避免 CI 卡住。
  • 写入前展示目标配置路径、profile、URL 和将新增的 MCP server 名称。
  • 覆盖已有 agent-capability-hub 配置前提示确认；带 --yes 时跳过确认。
Profile 配置面 规则对象 策略语义
外部 MCP 服务 source_type=mcp_service + source_key 沿用服务级 allow/deny；被拒绝服务不出现在 search，也不能被 execute 绕过。
Wiki 固有能力 builtin=wiki + kb_slug 不能关闭 wiki 工具，只能选择该 profile 可查阅哪些 KB。
CodeGraph 固有能力 builtin=codegraph + repo_key 不能关闭 codegraph 工具，只能选择该 profile 可查阅哪些代码仓库。
建议规则：未携带 profile 的管理/调试入口可见全部 active 资源；携带 profile 时，Wiki KB 和 CodeGraph 仓库默认不可见，需要在 Profile 资源范围中显式勾选。这样更符合项目级隔离预期。

7. 内置能力模型

Wiki 和 CodeGraph 不作为普通 MCP 服务登记，也不能被 Profile 直接关闭工具；它们是平台固定提供的内置服务。

Built-in
能力 source 表达 工具是否可关闭 Profile 控制对象 管理页面
外部 MCP source_type=mcp_service，source_key=mysql 可按服务启停，可按工具配置类型。 服务级 allow/deny。 MCP 服务、工具清单。
Wiki source_type=builtin，source_key=wiki 不可按 profile 关闭固定工具。 KB 范围。 知识库状态、文档同步状态。
CodeGraph source_type=builtin，source_key=codegraph 不可按 profile 关闭固定工具。 代码仓库范围。 代码仓库、同步任务、解析状态。
1. 管理资源管理员登记 KB 或代码仓库，维护状态和同步配置。
2. 绑定 Profile在 Profile 中选择可查阅的 KB 和代码仓库。
3. Search 发现MetaMCP 只返回当前 profile 可见的内置资源和固定工具。
4. Execute 校验执行前再次校验参数中的 kb_slug 或 repo_key 是否可见。
5. 写入日志记录资源、工具、耗时、失败阶段和响应摘要。

8. CodeGraph 集成需求

CodeGraph 用于管理代码仓库、定期同步并解析，向 MetaMCP 提供代码结构和代码查询能力。

CodeGraph

代码仓库管理

  • 登记仓库：repo_key、名称、Git URL、本地路径、默认分支、描述、标签。
  • 认证信息：支持 token/SSH key 引用，页面只显示掩码和更新时间。
  • 同步配置：手动同步、定期同步间隔、启停状态、解析策略。
  • 状态展示：clone/fetch、checkout、parse/index、last commit、last sync、错误信息。
  • 同步历史：每次同步 run 的阶段、耗时、状态、错误。

固定工具

  • codegraph.list_repositories：列出当前 profile 可见仓库和解析状态。
  • codegraph.repository_overview：仓库目录、语言、入口文件、最近解析摘要。
  • codegraph.search_code：按关键词、路径、语言、符号过滤搜索代码。
  • codegraph.get_file：读取指定仓库、ref、路径的文件内容。
  • codegraph.find_symbol：按函数、类、变量名查找定义和引用。初期可先做定义，引用分析作为增强。
同步状态 说明 页面表现
queued 等待同步或解析。 灰色状态，展示排队时间。
syncing 正在 clone/fetch/checkout。 蓝色状态，展示当前阶段。
parsing 正在生成代码索引或图谱。 蓝色状态，展示文件数和进度。
ready 可被查询。 绿色状态，展示 last commit、文件数、符号数。
error 同步或解析失败。 红色状态，点击查看失败阶段和错误详情。
disabled 暂停同步和查询。 灰色状态，MetaMCP search 不展示。
初期 CodeGraph 查询能力以“可管理、可同步、可按仓库授权、可查文件和符号”为验收标准；深度依赖图、跨仓影响分析和语义向量检索可以作为后续增强，不阻塞阶段二主线。

9. Wiki 固有能力需求

现有知识库能力需要在 Capability Hub 中以固定工具暴露，同时增加 Profile 级 KB 范围控制和状态页面。

Wiki

知识库管理视图

  • 列出平台管理的 KB：slug、名称、状态、描述、成员摘要。
  • 展示后端目标状态：mock、RagFlow、Weknora 等 backend target。
  • 展示文档数量、同步中数量、失败数量、最近同步时间、最近错误。
  • 点击 KB 查看文档同步状态和最近 job。

固定工具

  • wiki.list_kbs：列出当前 profile 可见 KB 和状态。
  • wiki.search：在指定 KB 中检索片段。
  • wiki.ask：在指定 KB 上问答。
  • wiki.get_document：读取指定文档元信息和同步状态，正文读取可后续开放。
Profile 行为 Search 行为 Execute 行为
Profile 允许 KB frontend-docs 返回 wiki 工具，并在资源摘要中展示 frontend-docs。 允许 wiki.search / wiki.ask 查询该 KB。
Profile 未允许 KB payroll 不返回该 KB 的资源摘要。 即使模型手写参数 kb=payroll，服务端也拒绝并记录 profile_policy_blocked。
KB 后端同步失败 资源仍可展示，但标记为异常。 查询失败时记录 builtin_backend_error，统计页可聚合到 wiki 维度。

10. 数据与接口影响

以下是需求级别的模型和 API 方向，具体字段可在实现计划中再细化。

API

建议新增/扩展表

  • tool_call_logs：增加 failure_stage、failure_owner、error_type、request_summary_json、response_summary_json、resource_type、resource_key。
  • profile_resource_rules：记录 profile 对 Wiki KB、CodeGraph repo 的可见范围。

11. 验收标准

本阶段验收要覆盖日志、统计、Profile、Wiki、CodeGraph 和 MetaMCP 服务端强制裁剪。

Acceptance
场景 验收标准
日志失败归因 构造平台参数解析失败、profile 拦截、MCP 连接失败、上游工具失败、Wiki 后端失败，各自产生稳定 error_type，日志页可筛选。
日志详情浮窗 日志列表点击请求或响应后打开浮窗，完整 JSON 可读、可复制；列表不再被大 payload 撑开。
统计页面 最近 24 小时、7 天、30 天可按 profile、service、tool、错误类型查看调用量、失败率、P95；点击统计行能跳转到日志筛选。
Project Profile 复制命令 Profile 页面能复制接入命令；执行命令时可交互选择项目级或用户级；写入配置后携带正确 X-Wiki-MetaMCP-Profile。
Wiki 固有能力 MetaMCP search 可发现 wiki 固定工具；profile 未允许的 KB 不可见且不可执行；页面能查看 KB 和后端同步状态。
CodeGraph 仓库管理 能登记代码仓库、配置认证引用、手动同步、查看同步/解析状态；ready 仓库可被固定工具查询。
CodeGraph Profile 裁剪 profile 只允许 repo A 时，search 只展示 repo A；execute 手写 repo B 参数会被拒绝并记录 profile_policy_blocked。
回归 现有 MCP 服务登记、工具同步、工具类型配置、profile 服务级 allow/deny、MetaMCP search/execute 继续通过。

测试分层

  • Storage：迁移、日志分类字段、统计聚合、资源规则 CRUD。
  • Governance：外部服务规则、Wiki KB 规则、CodeGraph repo 规则。
