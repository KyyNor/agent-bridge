Modification Plan

CodeGraph 集成与知识库 Web 完整管理改造计划

本计划围绕两个明确目标展开：将当前自研轻量代码解析替换为 colbymchenry/codegraph 的本地知识图谱能力；同时把知识库从“CLI + API 可用”提升为“Web 页面可完整管理”。

适用项目
agent-bridge

建议优先级
P0: CodeGraph 替换
P1: 知识库管理闭环

当前判断

CodeGraph 现状

当前 src/agent_bridge/codegraph/service.py 自行 clone 仓库后遍历文件， 只保存文件内容和 Python def/class 正则符号。它更像全文检索加简易符号表， 没有调用图、影响分析、跨语言 AST、框架路由识别和自动同步。

知识库 Web 现状

后端已经有知识库、文档、成员、同步、检索和问答 API；Vue 前端目前在 BuiltinsView.vue 里只展示知识库概览，没有创建知识库、上传文档、 文档详情、成员授权、同步任务处理和问答检索页面。

目标架构

1. 仓库登记 Web/接口保存 repo 元数据、权限、分支和状态。
2. 本地工作区 Agent Bridge 负责 clone/fetch 到受控目录。
3. CodeGraph 使用 codegraph init/index/sync/status 或 MCP 工具构建和查询 .codegraph/codegraph.db。
4. Builtin 能力 内置工具转发到 CodeGraph 的 search/explore/callers/callees/impact/node/files/status。
5. Web 管理 统一管理代码仓库、知识库、文档、成员、同步和问答检索。

CodeGraph 官方能力包括本地 SQLite 图谱、FTS5 搜索、MCP 工具、20+ 语言、调用关系、 影响分析、框架路由识别和文件监听自动同步。Agent Bridge 应复用这些能力，而不是再维护 自己的解析器和索引表。

一、CodeGraph 集成改造

1. 新增适配层

  • 新增 CodeGraphClient，封装 CodeGraph 的 CLI/MCP 调用。
  • 优先使用 codegraph serve --mcp 暴露的工具，覆盖 codegraph_explore 等核心能力。
  • 对 status、files、query 等命令保留 CLI JSON 路径，便于健康检查和同步流程。
  • 为每个 repo 以本地路径作为工作目录，避免跨仓库状态污染。

2. 替换索引逻辑

  • 删除或停用 _index_files、SYMBOL_PATTERN、codegraph_index_items 写入逻辑。
  • sync_repository 改为 clone/fetch 后执行 codegraph init -i 或 codegraph sync。
  • 同步结果来自 codegraph status --json 和进程退出码，写回 codegraph_sync_runs。
  • 保留 code_repositories 作为 Agent Bridge 的登记、权限和展示表。

3. 扩展内置工具

  • 保留兼容工具：search_code、get_file、find_symbol、repository_overview。
  • 新增语义工具：explore、callers、callees、impact、node、files、status。
  • 工具实现只做参数校验、权限校验、结果标准化，不再解析源码。
  • 继续接入现有 profile resource policy，资源类型保持 code_repo。

4. 依赖与部署策略

  • 启动时检测 codegraph 是否在 PATH，未安装时 Web 显示明确修复提示。
  • 文档推荐安装方式：npm i -g @colbymchenry/codegraph 或官方安装脚本。
  • 不要把 npm 包强行绑定进 Python 后端；默认走外部 CLI/MCP，降低 Node 运行时约束。
  • 可选后续优化：为热路径维护 MCP stdio 进程池，避免每次查询重复启动。

二、知识库 Web 完整管理

页面/模块 主要能力 需要补齐的 API 或前端动作
知识库列表 查看、创建、筛选、状态汇总、后端目标状态、同步失败数。 复用 GET /kbs、POST /kbs、GET /builtin/wiki/kbs，修正前端字段 document_count 与 doc_count 不一致。
知识库详情 文档列表、成员列表、同步状态、后端目标、最近错误。 组合 GET /docs?kb=、GET /kbs/{slug}/members、GET /status。
文档管理 上传、选择一个或多个知识库、稍后同步、查看详情、上传新版本、软删除、确认清理。 前端增加 multipart 上传；复用 POST /docs、POST /docs/{slug}/versions、POST /docs/{slug}/delete、POST /docs/{slug}/purge。
成员与权限 新增成员、修改角色、查看可管理者和贡献者。 先用 POST /kbs/{slug}/members 覆盖新增/更新；如需移除成员，新增删除 API。
同步中心 查看待处理、失败、成功任务；按后端筛选；手动同步当前用户或全量同步。 复用 GET /status、POST /sync；前端显示失败原因和重试入口。
检索与问答 选择知识库/后端，搜索 chunk，进行问答，展示引用片段和会话 ID。 复用 GET /search、POST /ask；前端提供结果列表和 answer panel。

实施阶段

Phase 1

CodeGraph 最小替换

  1. 加入 CodeGraphClient 和安装检测。
  2. 将同步改为调用官方 codegraph。
  3. 重写测试，证明不再写入自研索引。
  4. 让现有 search_code/find_symbol/status API 通过适配层返回结果。
Phase 2

语义能力接入

  1. 实现 MCP stdio 调用或短生命周期 MCP 调用器。
  2. 新增 explore/callers/callees/impact/node/files 工具。
  3. 保持 profile resource policy 和治理日志。
  4. 前端仓库详情展示图谱状态、文件树和影响分析入口。
Phase 3

知识库 Web 闭环

  1. 新增 Knowledge 路由或独立视图，不再塞在 Builtins 概览页里。
  2. 完成知识库、文档、成员、同步、搜索、问答六类交互。
  3. 补齐删除成员、编辑知识库基础信息等 API 缺口。
  4. 做端到端测试和前端构建产物更新。

后端改动清单

  • src/agent_bridge/codegraph/service.py：改为 orchestration service，只负责仓库同步、权限和调用 CodeGraph 适配层。
  • src/agent_bridge/codegraph/client.py：新增，封装 CLI/MCP 调用、超时、JSON 解析、错误归一化。
  • src/agent_bridge/capabilities/builtin_codegraph.py：工具列表扩展到官方 CodeGraph 语义工具。
  • src/agent_bridge/storage/schema.py：保留 repo 和 sync run；逐步废弃 codegraph_index_items，用 migration 或兼容空表处理老数据。
  • src/agent_bridge/api/routes/builtins.py：增加 repo 详情、状态、查询、文件树、影响分析接口，供 Web 页面调用。
  • src/agent_bridge/api/routes/knowledge.py：补齐删除成员、编辑知识库、后端目标管理等 Web 必需操作。

前端改动清单

  • 新增 KnowledgeView.vue，作为知识库管理主入口。
  • 新增 KnowledgeDetailView.vue 或同页 master-detail，承载文档、成员、同步、问答 tabs。
  • 扩展 api/client.ts 与 api/types.ts：补齐 knowledge CRUD、multipart 上传、sync、search、ask、codegraph status/query 类型。
  • 将 BuiltinsView.vue 保留为内置能力概览，把完整知识库管理迁移到独立页面。
  • 使用现有 shadcn-vue 风格组件，新增文件上传、确认弹窗、状态 badge、失败详情抽屉和结果引用列表。

迁移策略

兼容优先：第一版不删除 codegraph_index_items 表，只停止写入； API 返回结构尽量兼容现有测试和前端，内部数据源换成 CodeGraph。

风险控制：CodeGraph MCP/CLI 输出格式可能随版本变化。适配层必须集中处理版本检测、 JSON schema 校验、超时和错误信息，避免业务服务散落调用细节。

验收标准

  • 同步一个 TypeScript/Python/Go 任意仓库后，本地仓库目录出现 .codegraph/codegraph.db，Agent Bridge 不再生成自研索引内容。
  • 内置 CodeGraph 工具可以返回搜索、文件树、调用者、被调用者、影响分析和状态结果。
  • Profile resource policy 仍能限制某个用户或 profile 访问指定代码仓库。
  • Web 页面可以完成知识库创建、成员授权、文档上传、版本更新、删除、同步、状态查看、搜索和问答。
  • 失败场景可见：未安装 CodeGraph、clone 失败、index 失败、知识库后端同步失败都能在 Web 上看到明确错误。
  • 测试覆盖后端单测、API 集成测试、前端 build，以及至少一条知识库 Web E2E 流程。

建议实施顺序：先替换 CodeGraph 后端数据源，再扩展语义工具，最后做 Web 管理闭环。 这样能先把“方向错误的自研解析”收住，再把可视化管理补完整。
