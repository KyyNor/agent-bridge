PageIndex 内置后端部署说明

本方案把 PageIndex 作为 Agent Bridge 的内置知识后端运行。选择 backend_type = pageindex 后，Agent Bridge 不调用外部 PageIndex API，而是在本进程内调用 PageIndex SDK，并通过内网 LiteLLM 网关访问模型。

首期支持格式

PDFMarkdownMarkItDown 支持格式

其中 .docx 会通过 MarkItDown 转为 Markdown 后索引。老式 .doc 暂不支持，需要后续增加 LibreOffice 转换链路。

存储位置

索引与转换产物保存在：

/root/agent-bridge/data/backend/pageindex/{backend_slug}/{kb_slug}/

离线依赖准备

PageIndex、MarkItDown 全量可选依赖和 LiteLLM 已作为 Agent Bridge 主依赖安装。普通 uv sync 会直接带上 PageIndex 内置后端所需依赖；离线部署时，在有网构建机上按主依赖解析并打包 wheel 或镜像层，再拷贝到内网环境。

uv sync
uv export --format requirements-txt > requirements-pageindex.txt
pip download -r requirements-pageindex.txt -d offline-wheels/

内网服务器可以使用离线 wheel 安装：

pip install --no-index --find-links offline-wheels -r requirements-pageindex.txt

LiteLLM 网关配置

在管理页面新增 PageIndex 后端时填写：

  • LiteLLM Base URL：内网 OpenAI-compatible 地址，例如 http://litellm.internal:4000/v1
  • API Key：内网 LiteLLM key
  • Index Model：PageIndex 建索引用模型，例如 openai/qwen-long
  • Retrieve / Ask Model：检索和问答模型；留空时复用 Index Model

运行行为

文档上传仍走 Agent Bridge 现有同步任务。PageIndex 后端在同步任务中完成转换、索引和本地元数据记录。检索首期采用本地 PageIndex 结构内容的关键词匹配返回片段；问答会把检索片段作为上下文发给 LiteLLM。

后续增强

  • 增加 OpenAI Agents SDK 风格的 PageIndex tree-search 问答。
  • 增加 .doc 经 LibreOffice headless 转 .docx 的兼容链路。
  • 将长耗时索引任务进一步拆成独立 worker 或进程池。
