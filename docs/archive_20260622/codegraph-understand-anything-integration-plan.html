Architecture Proposal

CodeGraph 与 Understand Anything 共存集成初步方案

本文记录 Agent Bridge 后续接入 Understand Anything 的方向：CodeGraph 继续承担 agent 可调用的精确代码图谱能力，Understand Anything 承担面向人类的项目理解、架构浏览和导览展示能力。两者共享同一份 clone 后仓库，不互相替代。

建议结论 先接入 UA 的知识图产物和 Dashboard 入口，再逐步原生化摘要页。不要在第一阶段重写 UA Dashboard。

1. 能力定位

Agent Tooling

CodeGraph：面向 agent 的精确查询层

CodeGraph 已经在当前项目中作为内置代码仓库能力存在，支持仓库 clone、索引、文件查询、符号查询、调用关系、影响分析，并通过 repo-scoped MCP 暴露 codegraph_explore。

  • 优势：查询快，结构化程度高，适合工具调用和 profile governance。
  • 适用：agent 需要定位符号、查调用链、找影响面、围绕具体问题 explore。
  • 限制：返回结果更偏机器可读，不适合人类快速建立项目全局认知。
Human Understanding

Understand Anything：面向人类的理解层

Understand Anything 通过技能工作流分析项目，生成 .understand-anything/knowledge-graph.json，再由 Dashboard 展示架构、组件关系、业务域、导览和代码解释。

  • 优势：有 LLM 总结、导览、图谱 UI，更适合新人 onboarding 和人工探索。
  • 适用：用户想理解项目结构、核心模块、技术栈、功能域和变更脉络。
  • 限制：分析成本更高，且当前主要以 skill 形式交付，不是稳定 CLI。
因此集成原则是“共存互补”：CodeGraph 负责 agent 工具调用和精确语义检索，UA 负责面向人的项目理解和可视化探索。同步入口、权限、仓库目录由 Agent Bridge 统一托管。

2. 当前项目可复用入口

模块 现状 UA 集成方式
CodeGraphService 统一管理代码仓库注册、clone、sync、index、overview、query、explore。 增加 UnderstandAnythingService 或在 code repo service 下挂 understand 子服务，共用 paths.codegraph_dir / repo_key。
CodeGraphClient 封装 codegraph CLI。 新增 UnderstandAnythingClient，封装可用性检测、claude -p 调用、图谱读取和 dashboard 启动。
CodeRepoView.vue 仓库列表和详情弹窗，包含概览、查询、Explore 三个 tab。 详情弹窗增加 Understand tab，展示 UA 状态、摘要、图谱入口和生成按钮。
CodeGraphBuiltinProvider 内置能力只暴露 codegraph_explore。 新增 UA 内置工具，例如 code_repo_understand_overview、code_repo_understand_search，仍受 code repo resource rule 约束。

3. 目标架构

1. 注册仓库

用户在 Code Repos 页面注册 repo_key、Git URL、branch、分类和描述。

2. 统一 clone

Agent Bridge clone 到 AGENT_BRIDGE_ROOT/codegraph/{repo_key}。

3. CodeGraph 索引

运行 codegraph init/index，供 MCP、query、callers/callees 使用。

4. UA 分析

按需通过 claude -p 对同一目录执行 UA skill，生成知识图。

5. 展示与工具

前端展示摘要和 Dashboard 入口，agent 通过内置工具读取 UA 产物。

目录约定

数据所有权

  • Agent Bridge 拥有仓库注册信息、同步记录、权限规则和 UI。
  • CodeGraph 拥有自己的索引目录和 MCP 查询能力。
  • UA 拥有 .understand-anything 目录下的图谱、配置和中间产物。
  • Agent Bridge 只读取 UA 稳定产物，不直接修改 UA 的内部中间文件。

4. 通过 claude -p 调用 Understand Anything

UA 当前没有稳定 CLI 不是阻碍。服务端可以把 UA 当成“由 Claude 执行的技能工作流”：Agent Bridge 负责启动一个受控子进程，提示 Claude 在指定仓库目录执行 /understand 或等价技能流程，最终检查产物是否生成。

分析命令建议

claude -p "
Use the Understand Anything skill to analyze this repository:
/path/to/AGENT_BRIDGE_ROOT/codegraph/web-app

Requirements:
- Generate .understand-anything/knowledge-graph.json
- Use --language zh
- Prefer incremental update if the graph already exists
- Do not modify source code
- Report only final status, graph path, node count, edge count, and errors
"

Dashboard 命令建议

claude -p "
Use the Understand Anything dashboard skill for:
/path/to/AGENT_BRIDGE_ROOT/codegraph/web-app

Return the final local Dashboard URL including token.
Do not open unrelated browser windows.
"
实现时不要只信任 Claude 输出的“成功”。后端必须在进程结束后检查 .understand-anything/knowledge-graph.json 是否存在、是否是合法 JSON、是否能读取节点/边统计，以及是否对应当前 git commit。

5. 后端 API 与存储建议

新增 API

Endpoint 用途 返回重点
GET /code-repo/repositories/{repo_key}/understand/status 读取 UA 图谱状态。 available、graph_exists、node_count、edge_count、stale、last_error。
POST /code-repo/repositories/{repo_key}/understand/analyze 触发 UA 分析。 run id、状态、耗时、图谱路径、统计信息。
GET /code-repo/repositories/{repo_key}/understand/graph 返回完整或裁剪后的知识图。 前端图谱摘要或后续原生图视图需要的数据。
GET /code-repo/repositories/{repo_key}/understand/summary 返回轻量摘要，避免前端下载大图。 项目名、描述、语言、框架、模块、关键节点、导览。
POST /code-repo/repositories/{repo_key}/understand/dashboard 启动或获取 UA Dashboard URL。 tokenized local URL、进程状态、图谱路径。

存储表建议

MVP 可以先不入库，只从文件系统读取 .understand-anything 状态。进入可观测和调度阶段后，建议新增 run 表，结构类似 codegraph_sync_runs。 

CREATE TABLE IF NOT EXISTS understand_analysis_runs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  repo_key TEXT NOT NULL REFERENCES code_repositories(repo_key) ON DELETE CASCADE,
  status TEXT NOT NULL,
  stage TEXT NOT NULL,
  language TEXT NOT NULL DEFAULT 'zh',
  graph_path TEXT,
  node_count INTEGER,
  edge_count INTEGER,
  git_commit TEXT,
  error TEXT,
  duration_ms INTEGER,
  started_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  finished_at TEXT
);
权限模型沿用现有 code repo resource rule：只要用户或 profile 无权访问某个 code_repo，就不能读取 UA 摘要、图谱、Dashboard URL，也不能触发分析。

6. 前端展示策略

MVP

原生状态与摘要

在仓库详情中新增 Understand tab，显示 UA 是否安装、图谱是否存在、是否过期、节点/边数量、最近分析时间和错误信息。

复用

Dashboard 入口

提供“打开高级图谱”按钮。第一阶段优先跳转或 iframe 嵌入 UA 自带 Dashboard，避免重写复杂图交互。

后续

逐步原生化

把高频信息抽成 Agent Bridge 风格页面：项目概览、技术栈、模块列表、关键路径、导览和搜索。

为什么不第一阶段重写 UA Dashboard

  • UA Dashboard 已经包含图布局、节点详情、搜索、导览、业务域、代码查看、移动布局等功能。
  • 它的技术栈是 React/Vite，而当前管理台是 Vue。完整迁移会带来较高前端成本和维护风险。
  • 用户真正高频使用的可能是“摘要 + 跳转高级图谱”，先验证价值再决定重写范围更稳。

建议 UI 结构

仓库详情
  概览
  查询
  Explore
  Understand
    - 状态栏：UA 可用 / 图谱已生成 / 已过期 / 最近分析
    - 操作区：运行分析、强制重建、打开 Dashboard
    - 摘要区：项目说明、技术栈、主要模块、关键导览
    - 诊断区：最近一次分析日志、错误、耗时

7. Agent 内置工具建议

工具 能力 实现来源
codegraph_explore 保留现有工具，面向具体问题做代码结构探索。 CodeGraph MCP。
code_repo_understand_overview 读取 UA 图谱摘要，回答“这个项目是什么、怎么分层、关键模块是什么”。 knowledge-graph.json 归一化摘要。
code_repo_understand_search 在 UA 节点、summary、tags、descriptions 中做轻量搜索。 后端对 JSON 建轻量索引，或按需扫描。
code_repo_understand_tour 返回 UA 生成的 onboarding/tour 路线，适合新人理解项目。 UA graph 中的 tour / guide 相关字段。

8. 分阶段开发建议

Phase 1

产物识别与状态页

新增 UA status/summary API，从现有 clone 目录读取 .understand-anything/knowledge-graph.json。前端增加 Understand tab，但暂不触发分析。

Phase 2

通过 claude -p 触发分析

新增 UnderstandAnythingClient.analyze()，记录 run 状态和错误。默认手动触发，后续再考虑调度。

Phase 3

Dashboard 入口

通过 claude -p 调 UA dashboard skill，捕获 tokenized URL。前端提供打开按钮，必要时用 iframe 嵌入。

Phase 4

Agent 工具与治理

新增 UA 内置工具，并接入现有 profile resource rules、tool call logs、failure classification。

Phase 5

原生图谱体验评估

如果用户确实频繁在管理台内看图，再评估 Vue 原生图谱视图。优先重写高频摘要和搜索，不急着完整复制 UA Dashboard。

9. 风险与待确认问题

风险 影响 建议
UA skill 不是稳定 CLI 服务端自动化依赖 claude -p，失败模式更多。 封装 client，严格检查图谱产物；后续可给 UA 增加正式 CLI 或本项目内置 Node runner。
分析时间和 token 成本较高 不适合每次 sync 自动跑。 MVP 手动触发；调度阶段只在 commit 变化、用户开启配置后运行。
Dashboard token URL 管理 UA Dashboard 需要 tokenized URL，进程生命周期也要管理。 后端记录 dashboard 进程和 URL，URL 只给有 repo 权限的用户。
图谱 JSON schema 可能变化 原生摘要解析可能随着 UA 版本失效。 先做宽松解析和字段容错，保留原始 graph API 方便诊断。
安全边界 claude -p 会读取代码仓库，且 skill 可能生成文件。 提示词约束“不要修改源码”，后端只允许写 .understand-anything，必要时在工作副本上运行。
