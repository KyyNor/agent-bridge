OpenAPI 能力源接入设计

在 Agent Bridge 的能力目录中，OpenAPI 接入遵循“一个服务 source 下挂多个接口 tool”的结构。Spec 只作为页面导入辅助，最终执行契约以管理员保存的工具定义为准。

核心决策 数据模型 导入流程 执行契约 接口与页面 实施阶段

1. 核心决策

Source

OpenAPI 服务是能力集合

一个 OpenAPI 服务对应一个稳定 source/service，用于承载 base URL、认证、默认 headers、描述、标签和治理边界。

Tool

OpenAPI operation 是具体工具

每个接口 operation 保存为一个 openapi_tool，才会出现在 MetaMCP search(path=service_key) 和 execute 中。

Import

同步只在页面临时生效

解析 OpenAPI spec 后返回候选接口给页面，不写入候选表。管理员选择、编辑并保存后，才持久化为工具定义。

Safety

默认只开放查询类能力

GET 和 HEAD 可默认映射为只读工具。写操作默认 unconfigured，第一版不通过 MetaMCP 执行 action。

关键原则：Spec 是导入来源，openapi_tools 是最终执行契约。管理员保存后的 tool_name、字段描述、schema、请求映射和工具类型不被后续同步自动覆盖。

2. 数据模型

SourceType 扩展

class SourceType(str, Enum):
    builtin = "builtin"
    mcp_service = "mcp_service"
    openapi_service = "openapi_service"

openapi_services

字段说明
service_key稳定服务标识，和 MCP service_key 同级。
name, description, tags_json页面展示和能力搜索使用。
base_url执行接口时使用的基础 URL。
spec_url, spec_content_json页面导入辅助。可以只有 URL，也可以保存管理员粘贴的 spec。
auth_config_json, headers_json服务级认证和默认 headers。列表接口必须脱敏。
statusenabled, disabled, error。
last_synced_at, last_error最近一次页面导入解析的结果记录，不代表自动同步工具。

openapi_tools

字段说明
service_key, tool_name工具唯一键。Agent 执行时用这两个字段定位。
operation_id, method, path来源接口信息。手工添加工具时 operation_id 可为空。
display_name, description管理员可编辑的展示名和工具说明。
input_schema_json最终暴露给 Agent 的 JSON Schema。
request_mapping_json把 params 映射到 path、query、headers、body 的规则。
response_schema_json可选，用于页面提示和后续结果裁剪。
tool_type沿用 overview, search, detail, action, unconfigured。
tags_json, examples_json能力搜索、示例参数和页面辅助。
statusactive 或 inactive。移除不适合 AI 的接口时标记 inactive 或删除工具记录。

3. 导入与保存流程

1. 创建服务 管理员填写 service_key、base_url、认证、默认 headers、spec_url 或 spec 内容。
2. 解析 Spec 页面调用导入接口，后端解析 paths/operations 并返回候选工具数组。
3. 页面筛选 管理员勾选要加入服务的接口，未勾选接口不落库。
4. 人工编辑 管理员可以修改 tool_name、字段描述、schema、示例、tool_type。
5. 保存契约 点击保存后写入 openapi_tools，后续 execute 只读取保存后的工具定义。

导入接口返回值

导入接口只返回候选项，不写入 openapi_tools。

{
  "service_key": "crm-api",
  "operations": [
    {
      "operation_id": "getUser",
      "tool_name": "get_user",
      "method": "GET",
      "path": "/users/{id}",
      "display_name": "Get User",
      "description": "查询用户详情",
      "input_schema": {
        "type": "object",
        "properties": {
          "id": { "type": "string", "description": "用户 ID" }
        },
        "required": ["id"]
      },
      "request_mapping": {
        "path": { "id": "id" },
        "query": {},
        "headers": {},
        "body": null
      },
      "tool_type": "detail"
    }
  ]
}

4. 执行契约

Agent 侧继续使用统一 MetaMCP execute 入口，不感知底层是 MCP 还是 OpenAPI。

{
  "service": "crm-api",
  "tool_name": "get_user",
  "params": {
    "id": "u_123",
    "include_orders": true
  }
}

参数映射

  • request_mapping.path 映射到 URL path 参数。
  • request_mapping.query 映射到 query string。
  • request_mapping.headers 映射到请求 headers。
  • request_mapping.body 映射到 JSON body。复杂 body 推荐统一暴露为 body 字段。

安全限制

  • 执行前必须校验服务状态、工具状态、profile source policy 和 tool_type。
  • 第一版只允许 overview, search, detail 执行。
  • action 和 unconfigured 均返回明确阻断错误，不调用上游 API。
  • 上游 HTTP 失败应写入 tool_call_logs，failure owner 使用 OpenAPI 上游分类。

5. API 与页面改造

后端 API

接口用途
POST /capabilities/openapi-services新增或更新 OpenAPI 服务。
GET /capabilities/openapi-services列出 OpenAPI 服务，敏感 headers/auth 脱敏。
POST /capabilities/openapi-services/{service_key}/import解析 spec 并返回候选 operations，不落库。
GET /capabilities/openapi-services/{service_key}/tools列出已保存工具。
PUT /capabilities/openapi-services/{service_key}/tools/{tool_name}新增或更新一个工具定义。
DELETE /capabilities/openapi-services/{service_key}/tools/{tool_name}移除不适合 AI 使用的工具。
PUT /capabilities/openapi-services/{service_key}/tools/{tool_name}/type配置工具类型。

前端页面

  • 能力接入的新增服务表单增加类型选择：MCP / OpenAPI。
  • OpenAPI 服务详情页分为“已接入工具”和“从 Spec 导入”。
  • 导入结果只存在页面状态中，管理员保存后才写入数据库。
  • 已接入工具列表展示 method、path、tool_name、operation_id、tool_type、状态。

6. 实施阶段

阶段交付内容验收点
阶段一 新增 OpenAPI 数据表、repository、模型和基础 service API。 管理员可以创建 OpenAPI 服务并手工保存工具。
阶段二 实现 OpenAPI parser 和 import API。 Spec 解析结果返回到页面但不落库。
阶段三 接入 MetaMCP search/execute 分发。 search(path=service_key) 返回已保存 OpenAPI tools；只读工具可执行并写日志。
阶段四 前端能力接入页面支持 OpenAPI 服务和工具编辑。 管理员可以导入、筛选、编辑并保存接口工具。

7. 测试策略

  • Parser 测试：path/query/header/body 参数合并、operationId 缺失、tool_name 冲突、OpenAPI 3.x JSON/YAML。
  • Repository 测试：OpenAPI 服务和工具 CRUD、headers/auth 脱敏、删除工具后 search 不可见。
  • CapabilityService 测试：root search、service path search、profile allow/deny、tool_type 阻断。
  • Execute 测试：path/query/header/body 映射、上游 HTTP 错误分类、日志记录。
  • API 测试：import 不落库、保存后可见、删除后不可见。
  • 前端测试：服务类型切换、导入候选列表、编辑保存工具、删除不适合 AI 的接口。
