2. CLI 能力总览

weknora 是面向 WeKnora RAG 知识库服务的 Go CLI。它覆盖认证、知识库、 文档入库、检索、问答、Agent、MCP 和原始 API 调用等工作流。

命令 用途
auth 登录、登出、刷新 token、查看认证状态、打印凭据。
profile 管理多个连接目标，支持不同服务或租户之间切换。
kb 知识库创建、列表、查看、编辑、删除、置顶，以及 status/check。
doc 上传本地文件、从 URL 拉取、用 inline text 创建条目、列表、查看、下载、删除、等待解析。
search 按 chunks、知识库、文档或会话进行搜索。
chat 向知识库发起 RAG 问答，text 模式流式输出，json/ndjson 模式输出事件流。
session 管理会话并支持基于 Agent 的持续问答。
agent 自定义 Agent 的 CRUD、状态检查和调用。
chunk 查看和调试文档 chunk，用于 RAG 召回排查。
link / unlink 把当前目录绑定到某个知识库，后续命令可自动解析 --kb。
api 原始 HTTP passthrough，用于覆盖 CLI 未封装的深层 API。
mcp serve 通过 stdio 暴露只读 MCP 工具，供 AI agent 调用。
doctor 检查 base URL、认证、服务端版本和凭据存储。

CLI 独立 Go module，使用 Cobra 构建命令树。
SDK client/ 暴露 typed API，CLI 通过 replace 使用本地 SDK。

4. Wiki 相关能力

WeKnora 已有完整的 Wiki 模式：文档入库后由 Agent 自动生成结构化 Markdown 页面， 并维护页面之间的链接、索引、图谱、lint issue 和自动修复。

核心数据模型

Wiki 页面定义在 internal/types/wiki_page.go。主要字段包括： slug、title、page_type、content、 summary、aliases、source_refs、 chunk_refs、in_links、out_links 和 version。

页面类型 含义
summary 文档摘要页。
entity 实体页，例如人物、组织、地点。
concept 概念或主题页。
index Wiki 索引页。
log 操作日志页。
synthesis 跨文档综合分析页，由 Agent 在对话中生成。
comparison 比较分析页，由 Agent 在用户请求比较时生成。

HTTP API

Wiki 路由注册在 internal/router/router.go 的 RegisterWikiPageRoutes。

GET    /api/v1/knowledgebase/:kb_id/wiki/pages
POST   /api/v1/knowledgebase/:kb_id/wiki/pages
GET    /api/v1/knowledgebase/:kb_id/wiki/pages/*slug
PUT    /api/v1/knowledgebase/:kb_id/wiki/pages/*slug
DELETE /api/v1/knowledgebase/:kb_id/wiki/pages/*slug
GET    /api/v1/knowledgebase/:kb_id/wiki/index
GET    /api/v1/knowledgebase/:kb_id/wiki/log
GET    /api/v1/knowledgebase/:kb_id/wiki/graph
GET    /api/v1/knowledgebase/:kb_id/wiki/stats
GET    /api/v1/knowledgebase/:kb_id/wiki/search
POST   /api/v1/knowledgebase/:kb_id/wiki/rebuild-links
GET    /api/v1/knowledgebase/:kb_id/wiki/lint
POST   /api/v1/knowledgebase/:kb_id/wiki/auto-fix
GET    /api/v1/knowledgebase/:kb_id/wiki/issues
PUT    /api/v1/knowledgebase/:kb_id/wiki/issues/:issue_id/status

访问控制

Wiki 读取要求 Viewer+；页面创建、更新、删除、rebuild-links、auto-fix、issue 状态变更 要求知识库 owner contributor 或 admin。相关逻辑位于 internal/router/rbac.go。

Agent 工具

Wiki Agent 工具集中在 internal/agent/tools/wiki_*.go，包括读取页面、写页面、 重命名、替换文本、删除页面、读取源文档、创建/读取/更新 issue 等。

5. 值得复用的设计

  • 默认 JSON 输出。 面向自动化和 Agent 使用时，默认机器可读，比默认 text 更稳定。
  • stdout/stderr 分离。 stdout 只承载数据，stderr 承载日志、进度、错误，便于管道处理。
  • typed error + exit code。 认证、资源不存在、输入错误、服务端错误、确认要求等都映射到稳定退出码。
  • profile 模型。 支持多服务、多租户配置，并允许单次命令用 --profile 覆盖。
  • 目录绑定 KB。 .weknora/project.yaml 让当前目录天然关联知识库，减少重复传参。
  • dry-run。 写操作可先输出计划，方便自动化工具或 Agent 在执行前展示影响范围。
  • 破坏性操作确认。 删除等高风险操作默认需要确认；headless 场景下通过明确的 -y 放行。
  • MCP 只读优先。 mcp serve 只暴露 curated read-only surface，避免 Agent 意外改写数据。
  • raw API passthrough。 api 命令保留逃生口，CLI 不必一开始覆盖全部服务端接口。

6. 对当前 Python wiki CLI 的建议

当前项目已经初始化为 Typer CLI。后续如果目标是管理 WeKnora Wiki，建议按低风险、可验证的顺序推进：

阶段 建议命令 说明
基础连接 wiki profile、wiki auth、wiki doctor 先解决 host、token、profile、连通性和诊断。
只读 Wiki wiki page list、wiki page get、wiki search、wiki graph 优先实现读取能力，便于验证 API contract 和输出格式。
目录绑定 wiki link、wiki unlink 复用 WeKnora 的 KB 解析链：flag > env > project file > error。
写操作 wiki page create、wiki page edit、wiki page delete 增加 dry-run 和确认保护后再开放。
维护能力 wiki lint、wiki fix、wiki rebuild-links 封装服务端已有 lint、auto-fix、rebuild-links API。
Agent 集成 wiki mcp serve 先暴露只读工具，写入能力后续按显式确认引入。

推荐的首批命令形态

wiki doctor
wiki profile add local --host http://localhost:8080
wiki profile use local
wiki link --kb <kb_id_or_name>
wiki page list
wiki page get index
wiki page get concept/rag
wiki search "GraphRAG"
wiki graph --mode overview
wiki lint
