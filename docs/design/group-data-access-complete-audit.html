小组数据权限全域梳理

本方案以内部网络已经完成准入为前提，只解决“谁的数据归哪个小组、谁能看到和修改”这一件事。页面不做权限路由，普通 API 不引入细粒度功能 RBAC；Web、CLI、MCP 和后台运行统一在服务端按调用身份与数据归属裁决。

实施结论：本分支已把身份解析、小组映射、共享白名单、业务资源、运行数据、日志与代理入口接入同一套服务端数据范围裁决。业务台账与工作流产物均支持显式共享；工作流定义、任务、运行过程、脚本、记忆、Profile 和各类运行日志保持组内。浏览器可通过全局密码临时切换为维护管理员，裸访问和已有 SSO 均适用；前端只提供操作入口，不承担安全判断。

一、统一访问模型

可共享小组资源

知识库、MCP 服务、OpenAPI 服务、代码仓库、业务台账，以及单独发布的工作流产物。创建时归属一个组，可明确切换为共享；共享只开放读取和使用，修改权仍属于归属组。

不可共享小组数据

Profile、记忆块、工作流定义/任务/运行过程、用户脚本。它们始终只对归属组可见，子表、版本、记录和关联配置继承根数据归属。

运行数据与日志

工具日志、Agent 运行、工作流运行、脚本运行、评测运行、事件、输入输出和产物。创建时固化所属组，不能依据用户后来换组动态变化。

全局系统资源

后端连接、Agent 定义、系统配置、固定 Skill、内置脚本、分类和评测数据集目录等。继续由维护管理员管理，对所有组提供平台能力。

不可破坏的规则

  • 调用者来自统一账户系统用户 ID；CLI 以当前 Linux 用户名作为同一 Actor。
  • 裸访问或已有 SSO 的浏览器均可输入全局密码进入管理员模式；首次输入原子初始化密码，后续在系统管理页改密。
  • 普通用户未映射到数据组时，只能读取共享资源，不能创建小组数据或产生可持久化运行。
  • 创建小组资源时固化 owner_group_key；用户换组不迁移历史数据。
  • 共享白名单为知识库、MCP、OpenAPI、代码仓库、业务台账和工作流产物；其余资源不得暴露共享开关。
  • 共享资源所有已识别用户可读、可用于组装和运行，但只有归属组可修改、删除和改变共享状态。
  • 维护管理员是排障和迁移旁路，不改变资源真实归属，也不让管理员发起的派生运行错误归入管理员组。
  • 密码管理员与 server.toml admins 使用同一维护旁路，可查看和维护全部数据；退出管理员模式后恢复原 SSO 身份，裸访问则恢复未登录状态。
  • 子记录不单独选择归属或共享状态，必须从根资源或运行快照继承。
  • 前端不负责鉴权、不传自定义身份、不通过隐藏菜单提供安全性；后端列表过滤和详情拒绝必须一致。
  • 无法确认归属的历史数据进入维护队列，不得默认变成共享。
  • 共享资源被其他组使用后产生的日志归调用组，不因资源共享而反向暴露给资源归属组。

三、需要特别堵住的越权与错归属入口

  1. Dashboard 中间件绕过：/dashboard/{repo} 与 /memory-dashboard/{block} 在普通 FastAPI 依赖之前代理，当前 resolver 只有资源 key，没有 Actor。必须让代理请求完成身份解析和资源读取裁决，包括通过 Referer 或 token 推断的后续静态资源/API 请求。
  2. Agent 运行全局可读：列表、详情、事件、SSE、payload 当前直接访问 repository；只要知道 run key 就可能读取输入输出。所有入口必须先做统一 require_run_read。
  3. 文档多知识库挂载：共享的是知识库可见性，不是文档脱离归属。一个文档只能属于一个组，所有 placement 的知识库必须同归属组；维护管理员也不能制造跨组混合文档。
  4. 关联关系双边检查：KB 绑定代码仓库、Profile 绑定资源或记忆时，必须同时检查“能修改容器”和“能使用被关联资源”，仅检查 key 存在会绕过列表过滤。
  5. 后台调度身份：定时同步和工作流调度可以由系统进程执行，但运行归属要继承根资源，不能落到 scheduler/admin 所属组。系统执行上下文与数据归属必须分开表达。
  6. 共享资源日志：A 组共享 MCP，B 组调用后生成的工具日志属于 B 组；A 组拥有资源并不意味着可以查看 B 组的提示、参数和结果。
  7. 聚合与导出：统计、计数、导出、搜索建议和批量接口与普通列表同样可能泄露数据，必须在 SQL 层带组条件，不能取全量后再由前端隐藏。
  8. 历史数据默认共享：现有迁移把无法判定的旧资源设为共享，这不符合“明确标记为共享”。应在合并前改为按创建者映射归组；无法判定的进入维护态。业务台账和工作流产物也遵循显式共享，不自动扩大范围。

五、历史数据迁移规则

  1. 先按 created_by / actor 查当前用户-组映射；可解析的根资源归入对应组，默认 visibility=group。
  2. 知识库、MCP、OpenAPI、代码仓库、业务台账和工作流产物只有已有明确共享证据时才设为 shared；不能为了迁移方便自动共享。
  3. 根资源的子表通过外键或关联继承，不为每条子记录猜测创建人。
  4. 工具日志可按已有 actor 回填组；Agent 历史运行没有 Actor，不能根据 Profile 猜测，应标记为仅维护管理员可见。
  5. 工作流、脚本及其运行可优先从根定义继承；无根或关系损坏的数据进入未归属维护队列。
  6. 无法判断归属的存量数据保持 owner_group_key='' 且默认组内，不自动共享，仅维护管理员可见；本次不额外扩展通用资源转组功能。
  7. 用户以后换组只影响新建数据和直接调用运行；已有资源和历史运行不自动转移。

六、实施与提交记录

实现位于 codex/group-data-access worktree，各关键边界均独立提交，并以领域回归、全量 Python 测试和前端检查收口。

纠偏 1 · 权限模型与迁移基线
扩展资源类型 registry 和共享白名单；修正旧资源默认共享；增加未归属状态、资源转组/修复能力；补充文档单组归属不变量。
纠偏 2 · Profile 与跨资源关联
Profile 改为组内根数据；运行前校验；Profile-resource、Profile-memory、KB-repository 等关联执行双边访问检查。
纠偏 3 · 业务台账与记忆
业务台账接入归属和显式共享，跨组只读/查询；记忆保持组内；Profile 注入校验；封堵 Memory Dashboard 代理。
纠偏 4 · 工作流、脚本与模型评估
区分用户脚本和系统脚本；定义、版本、任务与运行建立归属继承；工作流产物支持逐项显式共享；调度器显式传递系统执行上下文与业务归属。
纠偏 5 · 工具日志与 Agent 运行
运行表固化组；工具日志、统计、Agent 列表/详情/events/SSE/payload/subagent/stop 统一范围检查；清理存储层全局读取入口。
纠偏 6 · 前端管理与代理入口收口
仅共享白名单资源显示共享开关；增加组归属/未归属修复界面；页面不做鉴权路由；检查 Dashboard、下载、导出、SSE 等非普通 JSON 入口。
纠偏 7 · 全域回归与迁移验收
覆盖同组读写、跨组拒绝、共享只读、管理员旁路、未映射用户、CLI Linux 用户、后台调度继承、用户换组历史不迁移；运行全量测试与前端检查。
扩展 8 · 密码管理员访问
增加裸访问/SSO 通用的管理员切换入口；首次原子设密；PBKDF2 哈希与 HttpOnly 管理员 Cookie；系统管理页改密与全会话失效；管理员复用现有跨组旁路，不复制业务资源权限判断。
复审 9 · 运行身份与详情收口
修正存量台账初始化顺序；定时工作流降权到 run 归属组并签发短期 capability；MCP/脚本 helper 校验 actor 与 run 写权限；文档详情过滤不可见 KB placement 和同步状态；Agent 在预留运行记录前校验 Profile 与 workflow lineage。
最终验证：./scripts/test.sh full -q 通过 1337 项 Python 测试；前端通过 249 项测试、Vue/TypeScript 类型检查和 Vite 生产构建。Ruff 与变更空白检查通过。

七、完成判定

只有同时满足以下条件，权限改造才算完成：

  • 任何列表、详情、搜索、统计、导出、下载、事件流和代理入口都无法读取其他组非共享数据。
  • 任何创建、修改、删除、绑定、运行和停止操作都在服务端完成组范围校验。
  • 共享白名单资源可跨组读取/使用但不能跨组修改；工作流共享范围只落在产物，不扩散到定义、任务、运行日志和 Agent 事件。
  • 所有运行数据可追溯到固化的归属组，后台调度和共享资源调用不会错归属。
  • 历史数据没有因无法判断归属而被扩大可见范围，未归属数据有明确维护流程。
  • Web、CLI、MCP 使用同一身份解析与策略服务，前端不承担安全职责。
  • 管理员密码不以明文保存；首次设置、错误密码、管理员退出、改密和旧会话失效均有自动化回归。
