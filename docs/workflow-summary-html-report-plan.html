Workflow 总结类工作流自动生成 HTML 报告

目标是在不改变 agent 检索行为的前提下，让“总结类”工作流在成功产生 Markdown 产物后，自动追加一次报告生成步骤，输出面向人类阅读的 HTML 报告。 artifacts_search 仍只服务 Markdown 产物；HTML 只用于前端查看与人工交付。

一、结论

新增工作流类型

在 workflow_definitions 增加 workflow_type，枚举先支持 operation 与 summary。

Markdown 仍是核心产物

原有 workflow 结束时仍输出 Markdown，并继续写入 workflow_artifacts，供智能体检索。

HTML 是派生报告

总结类 workflow 完成后，系统检查本轮 Markdown 产物，存在则调用报告 agent 生成 HTML，重复执行时覆盖同一任务/路径的当前报告。

二、数据模型

位置 变更 说明
workflow_definitions 新增 workflow_type TEXT NOT NULL DEFAULT 'operation' 前端新建/编辑工作流时可选择“操作 / 总结”。历史数据自动视为操作类，避免影响现有流程。
workflow_artifacts 建议复用现表，允许 format='html' HTML 报告仍作为产物存储，但 artifacts_search 默认过滤 format='markdown'。
workflow_artifacts.metadata_json HTML 报告写入 {"derived_from_artifact_id": "...", "report_kind": "human_html"} 便于 UI 把 Markdown 和 HTML 配对，也方便后续排查报告来源。
Artifact path 建议 HTML path 与 Markdown 同目录同基名：reports/a.md → reports/a.html 同一 workflow/task/version 重跑时沿用 current 覆盖机制；历史可通过 include_history 查看。

三、执行流程

运行原 workflow

保持当前 scheduler / runner 行为不变，workflow.js 领取任务、执行、输出 out/result.json 与 Markdown artifacts。

终态检查

当 workflow run 进入 completed 后，如果 definition 的 workflow_type='summary'，查询本轮 run_id 下的当前 Markdown artifacts。

存在 Markdown 产物才生成 HTML

如果没有正常产物，不调用报告 agent；run 保持 completed，但记录一条 warning 级 workflow log。

调用报告 agent

报告 agent 读取 Markdown 内容、workflow logs、agent events/subagent details 的摘要，生成完整 HTML 字符串。

保存 HTML artifact

以 format='html' 写入 workflow_artifacts。同 task/version/path 的旧 HTML 置为非 current，新报告成为 current。

前端查看

任务/进度/详情页继续保留 Markdown 查看；如存在 HTML 报告，额外展示“查看 HTML 报告”按钮，用 sandboxed iframe 或新弹窗渲染。

四、报告 agent 设计

建议新增内部服务方法，而不是要求用户在 workflow.js 里手写这个节点。这样可以保证总结类工作流统一有 HTML 报告，且普通操作类不受影响。

Agent name: workflow_html_reporter
Input:
{
  workflow: { workflow_key, name, description, workflow_type },
  run: { run_id, task_key, started_at, finished_at, duration_ms },
  markdown_artifacts: [
    { artifact_id, title, path, summary, content }
  ],
  run_logs: [...],
  agent_events_summary: "...",
  subagent_summaries: [...]
}

Output schema:
{
  "title": "string",
  "summary": "string",
  "html": "string",
  "source_artifact_ids": ["string"]
}

报告 HTML 约束

  • 必须是完整 HTML 文档，包含 <!doctype html>、内联 CSS、主体内容。
  • 禁止外链脚本；默认禁止 JS，除非后续明确允许。
  • 图片如果需要，优先使用 data URL 或本地已保存资产；第一阶段可先禁止图片，降低安全和路径复杂度。
  • 内容应面向人类阅读：标题、摘要、关键结论、证据/过程、风险与后续建议。
  • 不得把中间日志原样长篇堆入页面，应摘要化；必要证据可折叠展示。

五、后端改造点

模块 建议改动
storage/schema.py / migration 为 workflow_definitions 增加 workflow_type；保证历史 DB 自动补列。
automation/workflows/models.py 定义 WorkflowType = Literal["operation", "summary"] 或等价常量；定义 HTML report result schema。
automation/workflows/service.py definition upsert/list/get 返回 workflow_type；新增 generate_html_report_for_run(...)。
automation/workflows/scheduler.py 在 run completed 后调用报告生成 hook。报告生成失败不应把主 workflow 改成 failed，但要写 run log 和 run error warning 字段。
agent_runtime/service.py 复用现有 agent 调用能力，增加内部 agent name 或 preset；需要记录一个 agent_runs 关联到 workflow_run_id。
api/routes/workflows.py 支持 definition 的 workflow_type；artifact 查询允许前端按 format=html 或按 run_id 查 HTML 报告。
capability_hub/sources/builtin artifacts_search 明确默认只返回 format='markdown'；如后续需要，可新增人工用工具，而不是改变现有检索语义。

六、前端改造点

  • 工作流新建/编辑表单增加类型选择：操作、总结。默认操作。
  • 工作流详情页显示类型 badge；总结类可提示“结束后自动生成 HTML 报告”。
  • 进度页结束后：继续有“查看产物”打开 Markdown；若存在 HTML artifact，额外显示“查看 HTML 报告”。
  • 产物列表中 Markdown 与 HTML 最好配对展示：Markdown 标记“AI 检索”，HTML 标记“人类阅读”。
  • HTML 查看建议用弹窗 iframe：<iframe sandbox srcdoc="...">，避免报告内容污染管理台 DOM。

七、安全与失败策略

HTML 报告来自 agent 输出，必须按“不可信内容”处理。不要直接 v-html 注入主页面，优先用 iframe sandbox。
  • 报告生成失败：主 run 仍为 completed；写入 workflow run log：level=warning, stage=html_report。
  • 报告 HTML 超长：第一阶段可限制 2-5 MB，超限则失败并记录 warning。
  • 报告为空或非 HTML：保存前校验至少包含 <html 或 <body，否则视为失败。
  • 重复执行覆盖：依赖现有 is_current 机制，不物理删除旧报告。
  • 权限：HTML artifact 查看权限与 Markdown artifact 一致。

八、测试计划

层级 用例
Storage migration 默认值；保存 summary workflow；保存 html artifact；重复 run 后 current 覆盖。
Service operation workflow 不触发报告；summary workflow 无 Markdown 不触发；有 Markdown 调用 reporter 并保存 HTML。
API workflow definition 返回 type；artifact 按 run_id + format 查询；artifacts_search 默认不返回 HTML。
Agent Runtime reporter 输入包含 Markdown 内容与中间摘要；结构化输出解析失败时记录 warning。
Frontend 表单类型选择；进度页结束后 Markdown/HTML 按钮；iframe sandbox 渲染；无报告时按钮不显示或显示生成中/失败提示。

九、建议实施顺序

  1. 加 workflow_type 数据列、类型定义、API 往返，补 storage/API 测试。
  2. 前端表单和详情展示工作流类型，保证旧工作流默认操作类。
  3. 扩展 artifact 查询支持 format，并让 artifacts_search 默认过滤 Markdown。
  4. 实现 generate_html_report_for_run 服务方法，先用可 mock 的 reporter 调用，完成保存 HTML artifact 的闭环。
  5. 接入 scheduler completed hook：只对 summary workflow 且本轮有 Markdown 产物触发。
  6. 前端进度页和产物页展示 HTML 报告按钮，用 sandboxed iframe 查看。
  7. 最后补端到端测试：创建 summary workflow → run completed → markdown artifact + html artifact 均产生。

十、待确认点

  • 一个 run 可能产生多个 Markdown artifact：HTML 报告是每个 Markdown 一份，还是本轮 run 汇总一份？建议第一阶段“本轮 run 汇总一份”，路径为 reports/<run-task>.html 或约定 out/report.html。
  • 报告 agent 是否允许读取完整 subagent transcript？建议第一阶段读取摘要和 tool/event 概览，避免上下文过大。
  • HTML 报告是否需要进入历史版本列表？建议复用 artifact history，前端默认只显示 current。
  • 是否需要手动“重新生成 HTML 报告”按钮？建议第一阶段暂不做，后续可在 artifact 详情页增加。
