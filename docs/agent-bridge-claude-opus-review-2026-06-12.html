这批开发推进了很多有价值能力：CodeGraph/UA 集成、知识库 Web 管理、后端 CRUD、定时同步、Weknora agent 与检索策略、前端结构重组等。但当前不建议直接上线或合并到稳定分支，主要原因是管理 API 密钥泄露、知识库问答绕过成员权限、代码仓库读取接口缺少管理员校验，以及测试套件没有跟上新的白名单契约和前端目录结构。

阻断发现

P0GET /backends 无管理员校验且返回 api_key 明文

证据：src/agent_bridge/api/routes/knowledge.py:23-25 的路由没有 Depends(actor)；src/agent_bridge/knowledge/service.py:612-621 的 list_backends() 不接收 actor、不做 require_admin_user；src/agent_bridge/storage/repositories/knowledge.py:576-579 直接 SELECT * 返回 api_key。本地测试 test_backend_list_reports_weknora_type 也实际看到了响应包含 "api_key": "test-key"。

影响：任何能构造 X-Agent-Bridge-User 或访问该 API 的调用方都可能枚举知识后端配置并拿到 RagFlow/Weknora 密钥。前端编辑后端时已经使用“留空保持不变”的交互，不需要明文密钥。

建议：路由注入 current_actor，service 层强制 admin；列表和增改响应都只返回 api_key_set，不要返回 api_key；补 API 测试断言非 admin 403 且响应不含 api_key。

P0AgentBridgeService.ask() 绕过 KB 成员可见性

证据：src/agent_bridge/knowledge/service.py:419-444 调用 resolve_retrieval_strategy()，后者在 src/agent_bridge/knowledge/service.py:390-410 只按 slug 读 KB 和策略，不检查 actor 是否是管理员或 KB 成员。相比之下 search() 会先调用 _require_kb_visible(actor, kb_slug)。

影响：非成员只要知道 KB slug，就可能通过普通 /ask 接口读取回答和引用内容。builtin wiki 路径有 profile resource 检查，但底层 service 和 HTTP /ask 路径仍然缺口明显。

建议：ask() 入口先调用 _require_kb_visible(actor, kb_slug)；如果 profile_key 存在，还应明确校验该 profile 是否允许访问该 KB，再解析 retrieval override。补非成员问答禁止、profile 未授权问答禁止、管理员仍可问答的测试。

P1代码仓库读取/探索接口缺少管理员校验

证据：src/agent_bridge/api/routes/builtins.py:50-83 将 actor 传给 overview/files/query/explore/callers/callees/impact；但 src/agent_bridge/codegraph/service.py:160-281 对这些读取类方法没有 require_admin_user，只检查 repo 是否存在且 active。列表、创建、同步、UA 操作都有管理员校验，模型不一致。

影响：非管理员可能读取代码索引、文件内容、调用图和 explore 结果。对私有仓库或凭据 clone 的仓库，这相当于代码泄露面。

建议：如果这些是管理台接口，应在 route 或 service 统一 admin 校验；如果未来要对 agent 开放，应走 profile resource governance，而不是裸 API。补每个读取入口的非 admin 禁止测试。

P1测试套件当前红灯，且有多处旧契约未同步

验证命令 uv run pytest -q tests -m 'not ragflow and not weknora' 结果：11 failed, 294 passed, 8 deselected。其中本仓库内主要失败来自：前端视图重组后测试仍读旧路径；新增 search_all 后 builtin wiki tool_count 断言未更新；白名单模式改变后旧的 deny-only 默认允许测试未更新；后端列表响应契约变化未重新定义。

建议：先修安全问题，再统一更新测试契约。对视图重组类测试，应改读 views/monitoring/StatsView.vue、views/knowledge/KnowledgeView.vue、views/knowledge/CodeRepoView.vue、views/knowledge/KnowledgeProcessingConfigView.vue 等新路径。

其他风险

P2未知 backend 类型被静默忽略

src/agent_bridge/knowledge/backends/registry.py:26-45 对未知 backend_type 返回 None，构造 registry 时静默跳过。旧测试 tests/test_registry.py::test_registry_unknown_backend_type 期望抛 ValueError。静默忽略会让配置错误表现为“后端消失”，排障困难，也可能让 KB target 状态错判。

P2默认 pytest -q 会跑 live integration

pyproject.toml 只有 marker 声明，没有默认排除 ragflow/weknora。直接运行 uv run pytest -q 会尝试连接本机 RagFlow，当前结果为 18 failed, 295 passed，其中 7 个是 RagFlow 环境连接失败。建议给本地默认命令加 addopts = -m "not ragflow and not weknora"，并把 live 集成测试放到单独 CI job 或文档命令里。

P2Weknora agent eager ensure 会在 app 创建时打外部网络

AgentBridgeService.create() 里直接调用 ensure_weknora_agents()。测试中只要 TOML/DB 有 Weknora 后端，create_app() 就会请求 /api/v1/agents，虽然异常被 catch，但会拖慢启动并污染测试日志。建议延迟到首次使用、后台任务，或在配置上允许关闭启动期 ensure。
